# 3회차 · LLM 기반 콘텐츠 작성 심화

| 회차 | 시간 | 구성 | 선수 지식 |
|---|---|---|---|
| 3 / 10 | 4H | 핵심 개념 · 작성 체인 · 실습 3종 | 2회차(프롬프트 기초) |

## 학습 목표

이 회차를 마치면 다음을 할 수 있다.

- 복잡한 작업을 한 번에 시키지 않고 여러 단계로 나누는 **프롬프트 체이닝**을 설계할 수 있다.
- 기획 → 구성 → 초안 → 검수로 이어지는 대본 작성 체인을 직접 운용할 수 있다.
- AI를 활용해 기사의 사실 주장을 분해하고 **팩트체크 보조** 절차를 만들 수 있다.
- 기사 간 중복·유사도를 판단하는 데 AI가 어떻게 쓰이는지 이해한다.

---

## 1. 핵심 개념

### 1.1 프롬프트 체이닝: 한 번에 시키지 말 것

**[개념]** 2회차에서는 *한 번의 잘 만든 프롬프트*를 배웠다. 그러나 대본 작성처럼 복잡한 일은 한 번에 시키면 평범한 결과가 나온다. **프롬프트 체이닝**은 작업을 단계로 쪼개고, 앞 단계의 출력을 다음 단계의 입력으로 넘기는 방식이다.

| 한 번에 시키기 | 체이닝으로 나누기 |
|---|---|
| "이 주제로 3분 영상 대본 써 줘" | ① 핵심 메시지 3개 뽑기 → ② 구성(흐름) 짜기 → ③ 구성대로 대본 쓰기 → ④ 말맛·길이 다듬기 |
| 결과: 뭉뚱그려진 평범한 대본 | 결과: 각 단계에서 점검·수정 가능, 품질↑ |

**[팁]** 체인의 각 단계에서 사람이 한 번씩 개입(검토·수정)할 수 있다는 점이 가장 큰 이점이다. AI에게 통째로 맡기지 않고 **운전대를 사람이 쥔다.**

### 1.2 대본 작성 4단계 체인

**[개념]** 방송·유튜브 대본에 바로 쓸 수 있는 표준 체인이다.

| 단계 | 입력 | AI에게 시키는 일 | 사람이 점검할 것 |
|---|---|---|---|
| ① 메시지 | 주제·자료 | 핵심 메시지 3개, 타깃 시청자 정의 | 메시지가 정확/적절한가 |
| ② 구성 | ①의 결과 | 도입–전개–마무리 구성안 | 흐름이 자연스러운가 |
| ③ 초안 | ②의 결과 | 구성대로 대본 작성(말하기체) | 사실·표현·길이 |
| ④ 다듬기 | ③의 결과 | 호흡·자막 길이·금칙어 정리 | 방송 가능 수준인가 |

### 1.3 팩트체크 보조의 원리와 한계

**[개념]** AI는 검색엔진이 아니다. 학습 시점 이후의 사실을 모르고, 모르는 것도 그럴듯하게 지어낸다(환각). 그러므로 **AI에게 "사실인지 판정"을 맡기면 안 된다.** 대신 AI는 다음을 잘한다.

- 글에서 **검증이 필요한 사실 주장**을 빠짐없이 뽑아내기
- 각 주장에 대해 **무엇을, 어디서 확인해야 하는지** 점검 항목 만들기
- 확인용 질문 목록 만들기

> **AI가 직접 출처를 댄다면?** 검색·자료 연동(RAG) 기능이 있는 도구라면 출처 링크를 제시할 수 있다. 그래도 **링크를 직접 열어 원문을 확인**하기 전에는 사실로 취급하지 않는다. 이 원리는 핵심역량교육에서 더 깊이 다룬다.

### 1.4 기사 중복·유사도 판단 맛보기

**[개념]** "이미 비슷한 기사를 우리가 냈는가?"를 사람이 일일이 검색하기는 어렵다. AI는 문장의 **의미**를 숫자(벡터)로 바꿔, 표현이 달라도 의미가 가까우면 "유사"로 묶을 수 있다(임베딩·벡터 유사도). 이번 회차에서는 도구로 체험만 하고, 원리와 벡터 DB 활용은 후속 핵심역량교육에서 심화한다.

## 2. 작업 체인·템플릿

### 2.1 대본 체인 프롬프트(4단계)

> **① 메시지** — 너는 시사교양 PD다. 아래 자료에서 일반 시청자에게 전할 핵심 메시지 3개와 타깃 시청자를 정리하라. (자료: …)
>
> **② 구성** — 위 메시지로 3분(약 450자 분량) 영상 구성안을 만들어라. 도입(후킹)–전개–마무리로, 각 구간의 목적과 길이를 표로.
>
> **③ 초안** — 위 구성대로 말하기체 내레이션 대본을 작성하라. 한 문장은 짧게, 어려운 용어는 풀어서.
>
> **④ 다듬기** — 위 대본을 자막 기준 한 줄 16자 이내로 끊고, 호흡 표시(/)를 넣어라. 사실 확인이 필요한 문장은 [확인] 표시.

### 2.2 팩트체크 보조 프롬프트

> 아래 기사에서 **사실 주장**(수치·날짜·인용·인과관계)을 모두 추출해 표로 정리하라. 열: 주장 / 검증 방법 / 확인할 출처 후보 / 위험도(상·중·하). 의견·논평은 제외하라. (기사: …)

### 2.3 중복 판단 프롬프트

> 아래 [신규 기사]와 [기존 기사 목록]을 비교해, 주제·핵심 사실이 겹치는 정도를 0~100으로 매기고 근거를 한 줄로 설명하라. 표로 정리하라.

## 3. 실습

### [실습 1] 체이닝으로 3분 대본 완성 (60분)

실제 취재 자료나 보도자료 하나로 2.1의 4단계를 순서대로 진행한다. **각 단계 결과를 그대로 다음 단계에 붙여넣는다.** 중간에 사람이 수정한 내용이 최종 품질에 어떤 영향을 주는지 관찰한다.

| 단계 | AI 결과 요약 | 내가 수정한 점 |
|---|---|---|
| ① 메시지 | | |
| ② 구성 | | |
| ③ 초안 | | |
| ④ 다듬기 | | |

### [실습 2] 팩트체크 보조 (40분)

기존 기사 한 건을 2.2 프롬프트로 분석해 "확인이 필요한 주장" 목록을 만든다. 그중 위험도 '상'인 항목 2개를 골라 **실제로** 원문·공식 자료로 확인해 본다.

**[주의]** AI가 "사실입니다/거짓입니다"라고 단정해도 그대로 믿지 않는다. AI의 역할은 *판정*이 아니라 *점검 목록 작성*이다.

### [실습 3] 중복·유사 기사 판별 (30분)

비슷해 보이는 기사 2~3건을 2.3 프롬프트로 비교한다. AI의 유사도 점수와 본인의 판단을 비교하고, 어긋나는 지점을 토론한다.

## 4. 체크리스트

- [ ] 복잡한 작업을 체인으로 분해하는 이유를 설명할 수 있다.
- [ ] 대본 4단계 체인을 직접 끝까지 운용했다(실습 1).
- [ ] AI는 사실 *판정자*가 아니라 *점검 목록 작성자*임을 이해했다.
- [ ] 팩트체크 보조로 만든 항목을 실제 출처로 확인했다(실습 2).
- [ ] 의미 기반 유사도(임베딩)의 개념을 한 문장으로 말할 수 있다.

## 5. 핵심 요약

- 복잡한 작업은 **체이닝**으로 쪼개고, 단계마다 사람이 점검한다.
- 대본은 메시지 → 구성 → 초안 → 다듬기의 흐름으로 완성도가 올라간다.
- AI는 사실을 *판정*하지 못한다. 팩트체크에서는 **점검 목록을 만드는 보조자**로 쓴다.
- 의미 기반 유사도로 기사 중복을 가려낼 수 있으며, 원리는 후속 과정에서 심화한다.
