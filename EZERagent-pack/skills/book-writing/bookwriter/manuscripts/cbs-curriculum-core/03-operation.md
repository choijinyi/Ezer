# 평가 · 수료 기준 · 운영 안내

## 1. 평가 방법

핵심역량교육은 *코드를 돌려 업무를 자동화하는 능력*과 *그 효과를 정량으로 입증하는 능력*을 본다.

| 평가 축 | 대상 | 방식 |
|---|---|---|
| 과정 참여 | 전 회차 | 출석·실습 참여도 |
| 실습 코드 산출물 | 1~5회차 | 회차별 실습 코드·결과물(스크립트·JSON·음성/자막 등) |
| PBL 프로젝트 | 6회차 | 통합 파이프라인 + 효과 측정(정량) + 발표 |
| CBL 산출물 | 7회차 | 효율화 맵·AI 운용 가이드·피드백 루프 설계서 |

### PBL·CBL 평가 루브릭

| 평가 항목 | 배점 | 5점(최고) 기준 |
|---|:---:|---|
| 과제 정의 | 20 | 실제 병목을 풀 수 있는 크기로, 성공 지표를 숫자로 제시 |
| 기술 통합도 | 25 | 1~5회차 모듈을 end-to-end 파이프라인으로 조립 |
| 효과 측정 | 25 | 자동화 전후 시간·정확도를 정량으로 입증 |
| 운용·재현성 | 15 | 프롬프트·파라미터·검수 기준이 기록되어 재현 가능 |
| 전달력 | 15 | 발표가 명확하고 한계·다음 단계를 제시 |

## 2. 수료 기준

| 기준 | 요건 |
|---|---|
| 출석 | 전 80시간 중 **80% 이상** 참여 |
| 실습 이수 | 1~5회차 실습 코드 산출물 제출 |
| PBL 완수 | 6회차 통합 파이프라인 + 효과 측정 제출 |
| CBL 완수 | 7회차 효율화 맵·AI 운용 가이드 제출 |

수료 산출물(파이프라인·운용 가이드)은 **PoC 피드백 루프**와 **AX 실행계획**의 입력 자료로 직접 활용한다.

## 3. 실습 환경

| 항목 | 내용 |
|---|---|
| 언어·도구 | 파이썬 3.10+ (주피터 노트북·VS Code 어디서든 실행) |
| 주요 라이브러리 | `openai`/`anthropic`/`google-genai`(LLM API), `whisperx`(STT), `sentence-transformers`·`chromadb`/`faiss`(임베딩·벡터 검색) |
| API 키 | 외부 LLM·음성 API 키 필요. 코드에 직접 쓰지 않고 **환경 변수**(`os.environ`)로 관리하며, 파일·저장소에 키를 남기지 않는다 |
| 데이터 | CBS 뉴스 음성·영상 아카이브, 기사 DB 일부를 실습 입력으로 사용 |

> 모델·라이브러리 버전과 요금은 빠르게 바뀐다. 본 과정은 *원리와 파이프라인 구조* 중심이므로, 도구가 바뀌어도 학습 내용의 뼈대는 유효하다.

## 4. 자동화 시대에 더 중요해지는 4가지 원칙

코드로 업무를 자동화할수록 사람이 지켜야 할 원칙은 더 중요해진다. 전 회차에 걸쳐 반복한다.

1. **사실 확인(팩트체크)** — 자동 생성된 기사·요약·자막은 모두 *초안*이다. 발행 전 검증은 사람의 책임이며, 자동화 흐름에도 **사람 검수 게이트**를 반드시 둔다.
2. **저작권·출처** — 학습·생성·재가공에 쓰는 음성·영상·이미지의 권리·출처와 상업적 사용 가능 여부를 확인한다.
3. **개인정보·보안** — 미공개 취재원·사내 데이터·개인정보를 외부 AI API에 무분별하게 보내지 않는다. 민감 데이터는 처리 범위·보관 정책을 먼저 정한다.
4. **투명성·재현성** — AI 활용 콘텐츠는 사내 기준에 따라 고지하고, 자동화 코드·프롬프트·파라미터는 누구나 같은 결과를 재현할 수 있도록 기록·버전 관리한다.
