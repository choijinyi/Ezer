# 회차별 상세 커리큘럼

각 회차는 **학습 목표 → 핵심 내용 → 실습·산출물**의 흐름으로 구성된다. 회차당 10~12시간이며, 이론(핵심 개념)과 파이썬 실습 코드를 함께 진행한다. 실습 시간 외 나머지는 개념 강의·코드 리뷰·토론에 배정한다.

## 1회차 · AI 기술 심화와 프롬프트 엔지니어링 — 12H

**학습 목표**

- LLM이 토큰·임베딩·어텐션으로 "다음 토큰"을 예측하는 과정을 자기 말로 설명할 수 있다.
- temperature·top-p·max tokens 등 디코딩 파라미터를 의도적으로 조절할 수 있다.
- system/user 역할 분리, few-shot, Chain-of-Thought, 구조화된 출력(JSON)을 상황에 맞게 쓸 수 있다.
- LLM API를 파이썬으로 호출하고 API 키를 안전하게 다룰 수 있다.

**핵심 내용** — LLM 동작 원리 심화, 디코딩 파라미터, 고급 프롬프트 기법, LLM API 활용 기초, 프롬프트 최적화

**실습 · 산출물**

| 실습 | 시간 | 산출물 |
|---|:---:|---|
| 디코딩 파라미터 비교 | 60분 | 파라미터별 결과 비교 노트 |
| 기사 메타데이터 추출 — 구조화된 출력 | 60분 | JSON 스키마 + 추출 결과 |
| 프롬프트 최적화 루프 | 90분 | 최적화된 프롬프트 |

## 2회차 · 음성 AI와 STT 기술 실무 — 12H

**학습 목표**

- 음성이 텍스트로 바뀌는 과정(음향·언어 모델, 종단간/인코더-디코더)을 설명할 수 있다.
- WER·타임스탬프·세그먼트 개념으로 STT 품질을 정량적으로 가늠할 수 있다.
- 뉴스 특유의 오인식(고유명사·지명·전문용어)을 사전·프롬프트·후처리로 교정할 수 있다.
- WhisperX로 받아쓰고 정렬·화자 분리로 정확한 타임코드·화자를 얻을 수 있다.

**핵심 내용** — STT 원리·활용, 도메인 특화 STT, WhisperX 실습, CBS 뉴스 음성 데이터 활용, STT 기반 기사 소재 추출

**실습 · 산출물**

| 실습 | 시간 | 산출물 |
|---|:---:|---|
| WhisperX로 CBS 뉴스 음성 받아쓰기 | 70분 | 타임코드 녹취 |
| STT 후처리 교정 — 사전 치환 + LLM 교열 | 60분 | 교정 스크립트 + 교정본 |
| 녹취 → 기사 소재 후보 JSON 추출 | 80분 | 기사 소재 후보 JSON |

## 3회차 · 영상 분석 AI와 멀티모달 처리 — 12H

**학습 목표**

- 멀티모달의 원리(공통 표현 공간)와 한계를 자기 말로 설명할 수 있다.
- Gemini File API로 영상을 업로드하고 장면 요약·태깅·타임코드 추출을 시킬 수 있다.
- 구조화 출력(JSON)으로 장면별 메타데이터를 받아 후속 코드에 흘려보낼 수 있다.
- 영상에서 하이라이트·숏폼 컷 후보를 시간 구간과 함께 뽑아낼 수 있다.

**핵심 내용** — 멀티모달 AI 원리, Gemini API 영상 분석, 영상→텍스트 구조화, STT+영상 하이브리드 분석

**실습 · 산출물**

| 실습 | 시간 | 산출물 |
|---|:---:|---|
| Gemini로 뉴스 영상 장면 요약·태깅 | 90분 | 장면 메타데이터 |
| 영상→텍스트 구조화: 하이라이트·숏폼 컷 후보 추출 | 60분 | 컷 후보(타임코드) |
| 하이브리드: STT 자막 + 영상 태깅 타임라인 병합 | 90분 | 통합 타임라인 JSON |

## 4회차 · 데이터 분석과 검색·추천 기술 — 12H

**학습 목표**

- 임베딩을 검색용 벡터로 확장해 코사인 유사도로 "의미가 가까운 문서"를 찾는 원리를 설명할 수 있다.
- 긴 기사를 청크로 나눠 임베딩하는 이유와 기준을 적용할 수 있다.
- 키워드 검색과 시맨틱 검색의 차이를 설명하고 벡터 DB로 의미 검색을 돌릴 수 있다.
- 유사도 임계값으로 중복·유사 기사를 탐지하고 콘텐츠를 추천할 수 있다.

**핵심 내용** — 텍스트 임베딩·벡터 유사도, 벡터 DB(chromadb) 활용, 중복 탐지, LLM 기반 콘텐츠 평가

**실습 · 산출물**

| 실습 | 시간 | 산출물 |
|---|:---:|---|
| 기사 임베딩 + 코사인 유사도 의미 검색 | 75분 | 의미 검색 스크립트 |
| 벡터 DB 적재 → 시맨틱 검색 + 중복 탐지 | 90분 | 벡터 DB + 중복 경고 |
| LLM 기반 콘텐츠 평가 — 루브릭 자동 채점 | 75분 | 자동 채점 결과 |

## 5회차 · AI 기반 영상 제작과 기사 생성 자동화 — 12H

**학습 목표**

- 디퓨전 원리를 설명하고 이미지·영상 생성이 뉴스 제작의 어디(썸네일·B롤)에 쓰이는지 구분할 수 있다.
- 생성형 이미지·영상의 한계(사실 왜곡·일관성·딥페이크)와 금지선을 설명할 수 있다.
- 기사·영상에서 대본→TTS→자막→합성으로 이어지는 숏폼 자동화 파이프라인을 그릴 수 있다.
- 그 파이프라인 각 단계에 1~4회차 기술이 어디 들어가는지 짚을 수 있다.

**핵심 내용** — AI 이미지·영상 생성 심화, 숏폼 자동화 파이프라인, TTS·자막 동기화, 1~4회차 기술 결합

**실습 · 산출물**

| 실습 | 시간 | 산출물 |
|---|:---:|---|
| 기사 → 숏폼 대본 자동 생성 | 60분 | 씬 분할 대본(JSON) |
| 대본 → TTS 음성 + SRT 자막 생성·동기화 | 90분 | TTS 음성 + SRT 자막 |
| 미니 파이프라인 통합 | 90분 | 기사→숏폼 미니 파이프라인 |

## 6회차 · PBL 프로젝트 — CBS 업무 과제 해결 — 10H

**학습 목표**

- CBS M&C의 실제 업무 병목 하나를 **풀 수 있는 크기의 과제로 정의**하고 성공 지표를 숫자로 세울 수 있다.
- 1~5회차 기술 모듈(STT·영상 분석·검색·생성)을 **하나의 파이프라인으로 조립**할 수 있다.
- 앞 회차 코드를 함수로 불러와 한 케이스를 **end-to-end로 돌리는 통합 스크립트**를 작성할 수 있다.
- 자동화 전후 소요 시간·정확도를 **측정**해 개선 효과를 정량으로 제시할 수 있다.

**핵심 내용** — 실무 과제 기반 프로젝트 수행, 기술 모듈 통합, PoC 피드백 루프 연계

**실습 · 산출물**

| 실습 | 시간 | 산출물 |
|---|:---:|---|
| 과제 정의서 작성 | 60분 | 과제 정의서 + 성공 지표 |
| 파이프라인 프로토타입 구현 | 150분 | end-to-end 통합 스크립트 |
| 효과 측정과 발표 준비 | 90분 | 효과 측정 결과 + 발표자료 |

## 7회차 · CBL 도전 과제 — AI 업무 효율화 설계 — 10H

**학습 목표**

- CBL이 PBL과 어떻게 다른지 설명하고 전사 관점의 열린 과제로 사고를 확장할 수 있다.
- 콘텐츠 제작 전 과정(기획→취재→제작→편집→배포)의 병목을 진단하고 단계별 AI 적용·기대효과·난이도를 매핑할 수 있다.
- 병목 크기·자동화 난이도·적용 의지를 곱해 **효율화 우선순위**를 정량적으로 정할 수 있다.
- 표준 프롬프트·파라미터·검수 기준·금지선을 담은 **AI 운용 가이드** 초안을 문서화할 수 있다.

**핵심 내용** — 콘텐츠 제작 전 과정 효율화 설계, AI 운용 가이드, 피드백 루프 검증

**실습 · 산출물**

| 실습 | 시간 | 산출물 |
|---|:---:|---|
| 제작 전 과정 효율화 맵 | 90분 | 효율화 맵 + 우선순위 |
| AI 운용 가이드 초안 | 120분 | AI 운용 가이드 문서 |
| 피드백 루프 설계·검증 | 120분 | 피드백 루프 설계서 |
