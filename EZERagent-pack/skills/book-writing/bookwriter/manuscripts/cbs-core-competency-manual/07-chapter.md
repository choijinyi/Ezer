# 7회차 · CBL 도전 과제 — AI 업무 효율화 설계

| 회차 | 시간 | 구성 | 선수 지식 |
|---|---|---|---|
| 7 / 7 | 10H | 효율화 설계 · 운용 가이드 · 피드백 루프 | 1~6회차 전체 |

> 80시간 7회차 여정의 마지막이다. 6회차 PBL이 *개별 업무 과제*를 AI 파이프라인으로 풀어 봤다면, 7회차 CBL은 그 경험을 **콘텐츠 제작 전 과정의 효율화 설계**와 **AI 운용 가이드·피드백 루프 검증**으로 넓힌다. 여기서 만든 산출물은 그대로 PoC와 AX 실행계획의 초안이 된다.

## 학습 목표

이 회차를 마치면 다음을 할 수 있다.

- CBL(도전기반학습)이 PBL과 어떻게 다른지 설명하고, 전사 관점의 열린 과제로 사고를 확장할 수 있다.
- 콘텐츠 제작 전 과정(기획→취재→제작→편집→배포)의 병목을 진단하고, 단계별 AI 적용·기대효과·난이도를 매핑할 수 있다.
- 병목 크기·자동화 난이도·적용 의지를 곱해 **효율화 우선순위**를 정량적으로 정할 수 있다.
- 표준 프롬프트·파라미터·검수 기준·금지선을 담은 **AI 운용 가이드** 초안을 문서화할 수 있다.
- 베이스라인 대비 개선을 측정하는 **피드백 루프(3회전)**를 설계하고, 품질·안전 게이트로 검증할 수 있다.

## 1. CBL이란 무엇인가

**[개념]** CBL(Challenge-Based Learning, 도전기반학습)은 *정해진 답이 없는 열린 도전 과제*를 팀이 스스로 정의하고, 실제 환경에 적용하며 배우는 학습법이다. 6회차 PBL(Problem-Based Learning)이 "주어진 한 문제를 해결하는" 데 초점이 있었다면, CBL은 한 걸음 더 나아간다.

| 구분 | 6회차 PBL | 7회차 CBL |
|---|---|---|
| 과제 범위 | 개별 업무의 *한* 문제 | 콘텐츠 제작 *전 과정* |
| 해답 | 비교적 정해진 목표 | 열려 있음 — 무엇을 풀지부터 정함 |
| 관점 | 내 업무·내 팀 | 전사·조직 운영 관점 |
| 산출물 | 동작하는 파이프라인(PoC 후보) | 효율화 설계 + 운용 가이드 + 검증된 루프 |
| 다음 단계 | 효과 검증 | **AX 실행계획 초안으로 연결** |

**[개념]** 이번 회차의 목표는 "또 하나의 파이프라인을 만드는 것"이 아니다. 1~6회차에서 익힌 도구를 **조직이 반복해서 쓸 수 있는 형태**로 다듬는 것이다. 그래서 세 가지를 만든다 — ① 어디를 자동화할지 정하는 **효율화 맵**, ② 누가 돌려도 같은 품질이 나오게 하는 **운용 가이드**, ③ 효과를 숫자로 증명하는 **피드백 루프**. 이 셋이 PoC의 재료이자 AX 실행계획의 뼈대다.

**[주의]** 도전 과제라고 해서 "사람을 빼는 것"을 목표로 삼지 않는다. 자동화의 목표는 반복을 줄여 사람이 취재·판단·신뢰에 집중하게 하는 것이다. 효율화 설계의 모든 단계에는 **사람 검수 게이트**가 함께 설계되어야 한다.

## 2. 콘텐츠 제작 전 과정 효율화 설계

### 2.1 제작 5단계와 병목 진단

**[개념]** 콘텐츠 한 건은 보통 다섯 단계를 거친다. 사업계획서 진단에 따르면 콘텐츠 1건당 **3~6시간**이 들고, 그중 **소재 탐색이 전체 시간의 30~50%**를 차지하는 가장 큰 병목이다. 먼저 각 단계가 *무엇을 하고, 어디서 시간이 새는지*를 본다.

| 단계 | 하는 일 | 주요 병목 | 1~6회차 연결 |
|---|---|---|---|
| 기획 | 소재 탐색·아이템 선정 | **소재 탐색 30~50%** — 자료·트렌드 수집에 시간 집중 | 4회차 검색·임베딩 |
| 취재 | 녹취·인터뷰·자료 수집 | 녹취 전사·받아쓰기 수작업 | 2회차 STT |
| 제작 | 원고·구성·영상 소스 정리 | 영상 내용 파악·로그 정리 | 3회차 멀티모달 |
| 편집 | 원고 다듬기·자막·숏폼 | 자막 싱크·숏폼 컷 편집 | 5회차 생성·TTS |
| 배포 | 제목·메타데이터·채널 발행 | 제목 후보·태깅·중복 점검 | 1·4회차 프롬프트·중복탐지 |

**[팁]** 병목을 찾을 때 "느낌"이 아니라 **실측**으로 본다. 한 주 동안 단계별 소요 시간을 기록하면 어디에 시간이 몰리는지 금세 드러난다. 효율화는 *가장 큰 병목*부터 손대는 것이 원칙이다.

### 2.2 단계별 AI 적용·기대효과·난이도

**[개념]** 각 병목에 어떤 AI를 붙일 수 있는지, 기대효과와 구현 난이도는 어떤지를 정리한다. 난이도는 데이터 준비·정확도 요구·검수 부담을 종합한 체감 기준이다(하=바로 적용 / 중=프롬프트·약간의 코드 / 상=파이프라인·튜닝 필요).

| 단계 | AI 적용 | 기대효과 | 난이도 |
|---|---|---|---|
| 기획 | 임베딩 검색으로 과거 기사·자료 즉시 소환, LLM 트렌드 요약 | 소재 탐색 시간 대폭 단축(최대 병목) | 중 |
| 취재 | WhisperX STT로 녹취 자동 전사 + LLM 소재 추출 | 받아쓰기 제거, 녹취→초안 직결 | 중 |
| 제작 | Gemini 영상 분석으로 장면 로그·요약 자동 생성 | 영상 검토 시간 단축 | 상 |
| 편집 | LLM 원고 교열·숏폼 컷 제안, TTS 더빙·자막 싱크 | 편집 반복 작업 축소 | 중 |
| 배포 | 제목 후보 N개, 메타데이터 JSON 추출, 임베딩 중복 점검 | 발행 준비 시간 단축, 누락 방지 | 하 |

**[주의]** 기대효과는 *가설*이다. "대폭 단축"이 실제 몇 %인지는 3절의 피드백 루프로 측정하기 전에는 알 수 없다. 설계 단계에서 효과를 단정하지 말고, 측정 가능한 가설로 적어 둔다.

### 2.3 우선순위 선정 — 병목크기 × 자동화난이도 × 적용의지

**[개념]** 적용할 곳이 많을 때, 무엇부터 할지를 정하는 기준이 필요하다. 세 축을 각각 1~5점으로 매겨 곱한다.

- **병목 크기** — 그 단계가 잡아먹는 시간·빈도가 클수록 높다.
- **자동화 용이성** — 난이도의 *역수* 개념. 쉬울수록 높다(난이도 하=5, 상=1).
- **적용 의지** — 현업이 실제로 쓸 마음·여건이 되는가. 아무리 좋아도 안 쓰면 0이다.

> 우선순위 점수 = 병목크기 × 자동화 용이성 × 적용 의지

| 단계 | 병목크기 | 자동화 용이성 | 적용 의지 | 점수 | 트랙 |
|---|:---:|:---:|:---:|:---:|---|
| 기획(소재 탐색) | 5 | 3 | 5 | **75** | 단기 |
| 배포(제목·태깅·중복) | 3 | 5 | 4 | **60** | 단기 |
| 취재(STT 전사) | 4 | 3 | 4 | **48** | 중기 |
| 편집(숏폼·자막) | 3 | 3 | 3 | **27** | 중기 |
| 제작(영상 분석) | 4 | 1 | 3 | **12** | 장기 |

**[팁]** 점수가 곱셈인 이유는, 셋 중 *하나라도 0에 가까우면 전체가 죽기* 때문이다. 효과가 커도(병목 5) 아무도 안 쓰면(의지 1) 우선순위는 낮아야 맞다. 점수가 높은 **단기 트랙**부터 PoC로 검증하고, 낮은 것은 **중·장기 트랙**으로 미뤄 둔다. 이 트랙 구분이 곧 AX 실행계획의 우선순위 로드맵이 된다.

## 3. AI 운용 가이드와 피드백 루프 검증

### 3.1 운용 가이드 — "누가 돌려도 같은 품질"

**[개념]** 한 사람이 잘 쓰는 프롬프트는 자산이 아니다. **문서로 공유돼 팀 전체가 같은 결과를 내야** 자산이다. 운용 가이드는 1회차의 프롬프트 설계와 6회차 파이프라인을 *재현 가능한 표준*으로 묶는 문서다. 네 가지를 담는다.

| 구성 | 담는 내용 | 근거 회차 |
|---|---|---|
| 표준 프롬프트 | system 역할·지시문·few-shot 예시·출력 스키마 | 1회차 2~3절 |
| 파라미터 | 작업별 temperature·max tokens·모델 선택 | 1회차 1.3·3.3 |
| 검수 기준 | 사람이 확인할 항목과 합격선(예: 사실성·길이·말투) | 1회차 실습 3 |
| 금지선 | 절대 자동 발행하면 안 되는 경계 | 머리말 4원칙 |

**[주의]** 금지선은 가장 먼저 명문화한다. 예: ① 미공개 취재원·개인정보가 든 데이터를 외부 API로 보내지 않는다 ② AI 생성 사실 주장은 검수 전 발행 금지 ③ 저작권 미확인 음성·영상·이미지는 학습·생성 입력에서 제외 ④ AI 활용 콘텐츠는 사내 기준대로 고지. 이 선은 효율화보다 **항상 우선**한다.

### 3.2 피드백 루프 — 3회전 설계

**[개념]** PoC는 한 번에 완성되지 않는다. 사업계획서가 말하는 **피드백 루프 3회전**은 "돌려 보고 → 측정하고 → 고치는" 사이클을 세 번 반복해 운용 방법을 몸에 익히는 구조다. 1회차 실습 3의 프롬프트 최적화 루프를 *전 과정 효율화* 규모로 키운 것이다.

```
[베이스라인]  →  1회전  →  2회전  →  3회전  →  [내재화]
 현재 수작업      측정·     약점       게이트     표준 운용 가이드
 소요/품질        진단      보강       통과 확인   확정 + AX 반영
```

| 회전 | 초점 | 핵심 활동 | 통과 게이트 |
|---|---|---|---|
| 1회전 | 작동 검증 | 파이프라인을 실제 입력에 돌려 본다 | 끝까지 동작하는가 |
| 2회전 | 품질 개선 | 약점(오류·누락) 보고 프롬프트·검수 보강 | 품질 게이트 충족 |
| 3회전 | 안정·안전 | 회귀 점검·안전 게이트·운용 가이드 확정 | 안전 게이트 + 재현성 확보 |

**[개념]** 게이트는 *통과하지 못하면 다음으로 못 넘어가는* 관문이다. 두 종류를 둔다.

- **품질 게이트** — 결과가 합격선을 넘는가(예: 사실 정확도 95% 이상, 제목 후보 채택률 등).
- **안전 게이트** — 금지선을 어기지 않는가(개인정보 유출 0건, 미검수 자동 발행 0건). **안전 게이트는 품질과 무관하게 무조건 통과해야 한다.**

### 3.3 회귀 점검과 재현성

**[주의]** 2회전에서 프롬프트를 고쳐 한 약점을 잡았더니, 1회전에 잘되던 것이 망가지는 일이 흔하다. 이를 막는 것이 **회귀 점검**이다 — 고정된 테스트셋(예: 대표 입력 5~10건)을 매 회전 동일하게 돌려, 이전 점수보다 떨어지지 않았는지 확인한다.

**[주의]** 재현성을 위해 프롬프트·파라미터·모델 버전·테스트셋을 **버전 관리**한다. "지난주엔 잘됐는데"가 반복되면 자산이 되지 못한다. 운용 가이드에 버전 번호와 변경 이력을 남긴다.

### 3.4 AX 실행계획 연계

**[개념]** 3회전을 통과한 산출물(효율화 맵 + 운용 가이드 + 검증된 루프)은 그대로 **AX 실행계획 초안**이 된다. 2.3의 우선순위 트랙이 로드맵의 축이다.

| 트랙 | 대상 | 실행계획 내용 |
|---|---|---|
| 단기 | 점수 상위(기획·배포) | 즉시 PoC → 검증되면 현업 도입 |
| 중기 | 중간(취재·편집) | 데이터·도구 정비 후 단계 도입 |
| 장기 | 난이도 높음(영상 분석) | 기술 성숙·예산 확보 후 검토 |

## 4. 실습(설계 산출물)

> 이번 실습은 코드를 많이 짜는 것이 아니라, **재사용 가능한 설계 문서**를 만드는 데 있다. 1회차 프롬프트와 6회차 파이프라인을 가져와 채운다. 표는 그대로 운용 가이드·PoC 문서가 된다.

### [실습 1] 제작 전 과정 효율화 맵 (90분)

팀이 맡은 콘텐츠 유형(예: 노컷TV 뉴스 숏폼) 하나를 골라, 단계별로 표를 채운다. 우선순위 점수까지 계산해 단기/중기/장기 트랙을 확정한다.

| 단계 | 현재(수작업) | AI 적용안 | 기대효과(가설) | 난이도 | 병목5·용이5·의지5 → 점수 | 트랙 |
|---|---|---|---|:---:|:---:|---|
| 기획 | | | | | | |
| 취재 | | | | | | |
| 제작 | | | | | | |
| 편집 | | | | | | |
| 배포 | | | | | | |

**[팁]** "현재(수작업)" 칸에는 **실측 시간**을 적는다(예: 소재 탐색 90분/건). 이 값이 3절 베이스라인이 되고, 개선 효과를 %로 말할 수 있게 한다.

### [실습 2] AI 운용 가이드 초안 (120분)

단기 트랙으로 뽑힌 단계(예: 기획-소재 탐색, 배포-제목·메타데이터) 하나에 대해 표준 문서를 작성한다. 1회차의 프롬프트·파라미터와 6회차 파이프라인을 그대로 반영한다.

```
[운용 가이드] 배포 단계 — 제목 후보 & 메타데이터 추출   v1.0  (작성일/작성자)
```

### [실습 3] 피드백 루프 설계·검증 (120분)

운용 가이드를 고정 테스트셋에 3회전 돌려 베이스라인 대비 개선을 측정한다. 먼저 지표를 정의한다.

| 지표 | 정의 | 측정 방법 | 합격선 |
|---|---|---|---|
| 소요 시간 | 1건 처리 시간(분) | 수작업 vs AI 보조 실측 | 베이스라인 대비 30%↓ |
| 사실 정확도 | 오류 없는 결과 비율 | 사람 검수 0/1 채점 | 95% 이상 |
| 채택률 | 손대지 않고 쓴 결과 비율 | 발행본 대비 | 60% 이상 |
| 안전 위반 | 금지선 위반 건수 | 검수 기록 | **0건 (안전 게이트)** |

가벼운 측정 스니펫 — 처리 시간과 길이 규칙은 코드로 자동 채점한다.

```python
import time, json

TESTSET = ["원고1", "원고2", "원고3", "원고4", "원고5"]   # 고정 테스트셋

def run_round(round_no, pipeline):
    """한 회전: 테스트셋 전체를 돌려 시간·자동 채점 지표를 기록한다."""
    rows, t0 = [], time.time()
    for src in TESTSET:
        out = pipeline(src)                 # 운용 가이드대로 동작하는 함수
        auto_ok = len(out["titles"]) == 5   # 길이·형식 규칙은 자동 채점
        rows.append({"auto_ok": auto_ok})   # 사실성·채택은 사람이 0/1 추가
    elapsed = round((time.time() - t0) / len(TESTSET), 1)
    return {"round": round_no, "sec_per_item": elapsed, "rows": rows}

# 회전별 결과를 누적해 회귀 점검(이전 회전 대비 하락 여부)에 쓴다
log = [run_round(1, pipeline_v1)]   # 이후 v2, v3로 교체하며 append
```

**[주의]** 회귀 점검 — 2회전에서 어떤 지표를 올렸을 때 다른 지표(특히 사실 정확도)가 떨어지지 않았는지 *같은 표에서* 확인한다. 한 칸이라도 이전 회전보다 내려갔다면 원인을 찾고 운용 가이드를 되돌리거나 보강한다.

## 6. 핵심 요약

- **CBL은 열린 전사 과제다.** 한 문제를 푸는 PBL을 넘어, 콘텐츠 제작 전 과정을 조직이 반복해 쓸 형태로 설계한다.
- **효율화는 가장 큰 병목부터.** 소재 탐색(30~50%)이 1순위 후보이며, 우선순위는 **병목크기 × 자동화 용이성 × 적용 의지**의 곱으로 정한다 — 하나라도 0이면 전체가 0이다.
- **운용 가이드가 자산을 만든다.** 표준 프롬프트·파라미터·검수 기준·금지선을 문서화·버전 관리해야 누가 돌려도 같은 품질이 나온다.
- **효과는 루프로 증명한다.** 베이스라인 대비 3회전(작동→품질→안전)으로 측정하며, **안전 게이트는 항상 우선**하고 회귀 점검으로 후퇴를 막는다.
- 세 산출물(효율화 맵·운용 가이드·검증된 루프)은 곧 **PoC와 AX 실행계획의 초안**이다.

## 7. 과정을 마치며 — PoC와 AX 실행계획으로

80시간, 7회차의 여정이 끝났다. 1회차 LLM·프롬프트·API에서 출발해, 2회차 STT로 음성을 텍스트로, 3회차 멀티모달로 영상을 데이터로 바꿨다. 4회차에서 임베딩·검색·평가로 자료를 다루는 눈을, 5회차에서 생성·숏폼·TTS로 결과물을 만드는 손을 길렀다. 6회차 PBL에서 각자의 업무 과제를 파이프라인으로 풀었고, 이번 7회차 CBL에서 그것을 **전 과정 효율화 설계와 검증된 운용 체계**로 묶었다.

이제 교육은 끝나지만, 변화는 여기서 시작된다.

```
핵심역량교육(완료)  →  PoC(현업 검증)  →  AX 실행계획  →  전사 확대
 효율화 맵·운용         피드백 루프          단·중·장기        조직의
 가이드·검증 루프        3회전               우선순위 트랙       표준 업무
```

여러분이 만든 **효율화 맵**은 어디를 먼저 바꿀지 가리키는 지도이고, **운용 가이드**는 누구나 같은 결과를 내게 하는 매뉴얼이며, **검증된 피드백 루프**는 그 효과를 숫자로 증명하는 보증서다. 이 셋이 단기 트랙부터 현업 PoC로 들어가고, 3회전 검증을 거쳐 AX 실행계획으로, 다시 전사 표준으로 확대된다. 각 단계의 산출물이 다음 단계의 입력이 되는 순환 구조다.

도구와 모델은 계속 바뀔 것이다. 그러나 이 과정에서 익힌 **사고법 — 문제를 쪼개고, 자동화하되 사람이 검수하고, 효과를 측정하고, 재현 가능하게 기록한다 —** 은 오래 남는다. AI가 일을 대신하게 만드는 것이 목표가 아니었다. 반복은 기계에 맡기고, 사람은 취재·판단·신뢰에 집중하는 것이 목표였다. 80시간의 수고에 깊이 감사드리며, 이제 현업의 PoC에서 그 성과를 증명할 차례다.
