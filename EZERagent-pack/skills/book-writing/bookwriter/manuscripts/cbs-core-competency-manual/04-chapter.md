이 회차를 마치면 다음을 할 수 있다.

- 1회차식 구조화 출력(JSON)으로 LLM에게 콘텐츠를 루브릭 채점시켜, 품질 평가 초안을 자동으로 받을 수 있다.

## 1. 텍스트 임베딩과 벡터 유사도

1회차에서 "토큰을 임베딩(숫자 벡터)으로 바꾸면 의미가 가까운 말이 가까운 좌표에 놓인다"고 했다. 4회차는 그 성질을 *검색·중복·추천*이라는 실무로 본격 활용한다.

### 1.1 문장·문서 임베딩 — 한 덩어리를 한 점으로

**[개념]** 1회차의 임베딩이 *토큰 단위*였다면, 검색에서는 문장·문단·기사 한 덩어리를 통째로 하나의 벡터로 바꾼다. 이렇게 하면 기사 한 건이 고차원 공간의 *한 점*이 되고, "비슷한 기사 찾기"는 곧 "가까운 점 찾기"가 된다. 의미가 비슷하면 표현이 달라도 가까운 좌표에 놓이는 것이 핵심이다 — "물가가 올랐다"와 "장바구니 부담이 커졌다"는 글자는 겹치지 않지만 벡터로는 가깝다.

### 1.2 코사인 유사도 — 두 벡터가 같은 방향을 보는가

**[개념]** 두 벡터가 얼마나 비슷한지는 보통 **코사인 유사도(cosine similarity)**로 잰다. 두 벡터 사이 각도의 코사인 값으로, **1에 가까울수록 같은 방향(=의미가 비슷)**, 0이면 무관, 음수면 반대 방향이다. 벡터의 *길이*가 아니라 *방향*만 보기 때문에, 문서 길이에 덜 휘둘리고 의미 비교에 적합하다.

| 코사인 유사도 | 해석 | 뉴스 업무에서의 의미 |
|---|---|---|
| 0.95 이상 | 거의 같은 글 | 중복/재게시 의심 (실습 2) |
| 0.80~0.95 | 같은 사건·주제 | 유사 기사, 후속·관련 기사 후보 |
| 0.50~0.80 | 느슨하게 관련 | 추천 후보(맥락 참고) |
| 0.50 미만 | 사실상 무관 | 제외 |

**[주의]** 위 구간은 *출발점일 뿐* 절대 기준이 아니다. 임계값은 **임베딩 모델·데이터·언어마다 달라서**, 실제 기사 표본으로 분포를 직접 확인해 정해야 한다(실습 2). 숫자를 그대로 믿지 말 것.

### 1.3 청크(chunk) — 긴 글은 잘라서 임베딩한다

**[개념]** 기사 전체를 벡터 하나로 뭉치면, 한 기사 안의 서로 다른 소주제가 *평균*돼 흐려진다. 그래서 긴 문서는 문단·일정 길이 단위로 **청크**로 나눠 각각 임베딩한다. 검색은 청크 단위로 가장 가까운 조각을 찾고, 필요하면 그 청크가 속한 원문으로 되돌아간다. 이는 3절의 RAG와 5회차 파이프라인에서 그대로 쓰인다.

- **청크 크기** — 너무 작으면 문맥이 끊기고, 너무 크면 의미가 뭉개진다. 뉴스 본문은 보통 문단 또는 수백 자 단위가 무난하다.
- **겹침(overlap)** — 청크 경계에서 문장이 잘려 맥락이 끊기지 않도록, 청크 끝을 조금 겹쳐 자르면 검색 품질이 올라간다.

### 1.4 임베딩 모델 — 로컬 모델 vs 임베딩 API

**[개념]** 텍스트를 벡터로 바꾸는 도구는 크게 두 갈래다.

| 방식 | 예시 | 장점 | 주의 |
|---|---|---|---|
| 로컬 모델 | `sentence-transformers`(예: 다국어 MiniLM) | 데이터가 외부로 안 나감, 호출 비용 0 | 첫 모델 다운로드 필요, 품질은 모델에 따라 편차 |
| 임베딩 API | OpenAI·Gemini 임베딩 | 설치 간단, 대체로 고품질 | 데이터가 외부로 전송됨, 호출당 과금 |

**[주의]** 미공개 취재원·사내 기사 원문·개인정보를 *외부 임베딩 API*에 보내는 순간 데이터는 회사 밖으로 나간다. 민감 데이터는 **로컬 임베딩(sentence-transformers)**을 우선 검토하고, 외부 전송이 불가피하면 처리·보관 범위를 먼저 정한다(머리말 3원칙).

## 2. 벡터 DB와 시맨틱 검색

### 2.1 키워드 검색 vs 시맨틱 검색

**[개념]** 기존 검색은 대부분 **키워드 검색**이다. "물가"를 검색하면 그 글자가 든 기사만 찾는다. 표현이 다르면("장바구니 부담") 놓친다. **시맨틱(의미) 검색**은 질의도 벡터로 바꿔, *의미가 가까운* 문서를 글자 일치와 무관하게 찾는다.

| 구분 | 키워드 검색 | 시맨틱 검색 |
|---|---|---|
| 매칭 기준 | 글자(단어)의 일치 | 의미(벡터)의 근접 |
| 강점 | 고유명사·정확한 용어 | 동의어·바꿔 쓴 표현·주제 |
| 약점 | 표현이 다르면 놓침 | 정확한 코드·이름은 덜 정확 |
| 뉴스 활용 | 인명·기관명 정확 검색 | 아카이브에서 *비슷한 사건* 찾기 |

**[팁]** 둘은 경쟁이 아니라 보완이다. 실무에서는 키워드와 시맨틱을 함께 쓰는 **하이브리드 검색**이 가장 안정적이다. 우선 의미 검색의 감을 잡고, 정확한 고유명사가 중요한 검색에는 키워드를 더한다.

### 2.2 벡터 DB — 가까운 점을 빠르게 찾는 저장소

**[개념]** 기사가 수만 건이면, 질의 벡터와 모든 기사 벡터의 거리를 매번 전부 계산하기엔 느리다. **벡터 DB**는 벡터를 저장하고 **인덱싱**해 "가장 가까운 k개(top-k)"를 빠르게 찾아 준다. 이것이 **최근접 이웃 검색(nearest neighbor search)**이다.

- 이 교재는 설치가 간단하고 로컬에서 도는 **`chromadb`**를 기본으로 쓴다. 대규모·고성능이 필요하면 `faiss` 같은 대안이 있다(원리는 같다).
- 벡터와 함께 **메타데이터**(기사 ID·날짜·카테고리·출처)를 저장하면, "2026년 + 경제 카테고리 안에서 의미 검색" 같은 **필터 + 시맨틱** 검색이 가능하다. 아카이브·기사 DB에 그대로 적용된다.

### 2.3 검색 파이프라인의 뼈대

**[개념]** 시맨틱 검색은 항상 같은 골격을 가진다. 이 구조가 2.x 실습과 3절 RAG의 공통 토대다.

```
①문서 수집 → ②청크 분할 → ③임베딩(벡터화) → ④벡터 DB에 적재(메타데이터 포함)
                                                        ↓
                          ⑤질의 임베딩 → ⑥top-k 최근접 검색 → ⑦결과 활용(검색/중복/추천/RAG)
```

①~④는 **한 번 만들어 두는 색인 단계**, ⑤~⑦은 **질의가 들어올 때마다 도는 검색 단계**다. 색인을 미리 만들어 두면 검색은 빠르다.

## 3. 응용 — 중복 탐지·추천·콘텐츠 평가

같은 "가까운 점 찾기"가 용도에 따라 중복 탐지·추천·RAG·평가로 갈라진다.

### 3.1 중복·유사 기사 탐지

**[개념]** 새 기사가 들어올 때 기존 기사들과의 코사인 유사도를 계산해, **임계값 이상이면 중복/유사로 경고**한다. 재게시·복붙·표절 의심을 자동으로 1차 거른다. 아카이브 정리(같은 사건의 중복 영상·기사 묶기)에도 쓴다.

**[주의]** 유사도가 높다고 *반드시 중복은 아니다.* 같은 사건을 다른 각도로 쓴 정당한 후속 기사도 유사도가 높게 나온다. 자동 탐지는 **"사람이 확인할 후보를 추려 주는 것"**까지이고, 중복·표절 *판정*은 사람의 몫이다.

### 3.2 관련 콘텐츠 추천

**[개념]** "이 기사를 본 독자에게 비슷한 기사 추천"은 곧 *이 기사 벡터와 가까운 다른 기사 top-k*다. 행동 로그가 없어도, 콘텐츠 임베딩만으로 **콘텐츠 기반 추천**이 된다. 노컷TV 영상 설명·기사 본문에 적용하면 "관련 영상/기사" 줄을 자동으로 채울 수 있다.

**[주의]** 추천은 *필터 버블*을 만들 수 있다. 비슷한 것만 계속 밀면 시야가 좁아진다. 다양성·최신성 같은 보정과, 부적절한 추천이 없는지 사람의 점검이 필요하다.

### 3.3 RAG — 검색 증강 생성 (한 단락)

**[개념]** **RAG(Retrieval-Augmented Generation)**는 *먼저 검색해서 근거 문서를 찾고(2절), 그 문서를 프롬프트에 넣어 LLM이 답하게* 하는 방식이다. LLM이 모르는 사내 데이터·최신 사건을 답에 반영하고, 환각을 줄이며, "어느 기사를 근거로 했는지" 출처를 댈 수 있게 한다. 이 회차의 검색 파이프라인(색인→top-k) 위에 1회차의 LLM 호출을 얹으면 바로 RAG가 된다. 5·6·7회차 자동화의 핵심 구조다.

### 3.4 LLM 기반 콘텐츠 평가 — 루브릭 자동 채점

**[개념]** 검색이 "비슷한 것 찾기"라면, 평가는 "기준에 맞는지 점수 매기기"다. 1회차의 **구조화 출력(JSON)**을 그대로 써서, LLM에게 **루브릭(채점 기준표)**으로 기사를 채점시키면 품질 평가 *초안*을 자동으로 받을 수 있다. 예: 정확성·균형성·제목 적합성을 각각 1~5점과 근거로.

**[주의]** LLM 점수도 *초안*이다. 모델은 그럴듯한 점수를 줄 뿐 진실을 보장하지 않는다. 대량 기사의 *우선순위 선별*(낮은 점수부터 사람이 검토)에는 유용하지만, **최종 품질 판단·발행 결정은 사람**이 한다.

### [실습 1] 기사 임베딩 + 코사인 유사도 의미 검색 (75분)

기사 몇 건을 로컬 모델로 벡터화한 뒤, 질의와 가장 가까운 기사 top-k를 찾는다. 글자가 겹치지 않아도 *의미*로 찾아지는 것을 확인한다.

```python
# pip install sentence-transformers numpy
from sentence_transformers import SentenceTransformer
import numpy as np

# 다국어 임베딩 모델(첫 실행 시 자동 다운로드). 데이터가 외부로 나가지 않는다.
model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

articles = [
    "한국은행이 기준금리를 동결하며 물가 안정에 무게를 뒀다.",
    "장바구니 물가가 올라 소비자 부담이 커지고 있다.",
    "프로야구 개막전에서 홈팀이 끝내기 승리를 거뒀다.",
    "정부가 지역 소상공인 대상 금융 지원 대책을 발표했다.",
]

# 문서 임베딩(검색 색인). 한 번 만들어 두고 재사용한다.
doc_vecs = model.encode(articles, normalize_embeddings=True)  # 정규화하면 내적=코사인

def search(query, top_k=2):
    q = model.encode([query], normalize_embeddings=True)[0]
    sims = doc_vecs @ q                      # 정규화했으므로 내적이 곧 코사인 유사도
    order = np.argsort(sims)[::-1][:top_k]    # 유사도 높은 순 top-k
    return [(articles[i], float(sims[i])) for i in order]

for hit, score in search("물가 부담이 커졌다"):   # '물가/부담'이 그대로 없어도 찾아짐
    print(f"{score:.3f}  {hit}")
```

|---|---|---|---|
| "물가 부담이 커졌다" | | | |
| "야구 경기 결과" | | | |
| "소상공인 돕는 정책" | | | |

### [실습 2] 벡터 DB(chromadb) 적재 → 시맨틱 검색 + 중복 탐지 (90분)

기사를 벡터 DB에 메타데이터와 함께 적재해 검색하고, 새 기사가 기존 기사와 **임계값 이상 유사하면 경고**한다.

```python
# pip install chromadb sentence-transformers
import chromadb
from chromadb.utils import embedding_functions

# chromadb 내장 임베딩 함수도 sentence-transformers를 쓴다(로컬).
emb_fn = embedding_functions.SentenceTransformerEmbeddingFunction(
    model_name="paraphrase-multilingual-MiniLM-L12-v2"
)

client = chromadb.Client()                       # 메모리 DB(영구 저장은 PersistentClient)
col = client.create_collection(
    "cbs_articles", embedding_function=emb_fn,
    metadata={"hnsw:space": "cosine"},           # 거리=코사인 거리 → (1 - distance)이 코사인 유사도
)

# ①~④ 색인: 본문 + 메타데이터(날짜·카테고리) + 고유 id
col.add(
    documents=[
        "한국은행이 기준금리를 동결하며 물가 안정에 무게를 뒀다.",
        "정부가 지역 소상공인 대상 금융 지원 대책을 발표했다.",
        "프로야구 개막전에서 홈팀이 끝내기 승리를 거뒀다.",
    ],
    metadatas=[
        {"date": "2026-05-20", "category": "경제"},
        {"date": "2026-05-21", "category": "경제"},
        {"date": "2026-05-22", "category": "스포츠"},
    ],
    ids=["a1", "a2", "a3"],
)

# ⑤~⑦ 시맨틱 검색: 경제 카테고리 안에서 의미가 가까운 기사 top-2
res = col.query(
    query_texts=["소비자 물가와 가계 부담"],
    n_results=2,
    where={"category": "경제"},                  # 메타데이터 필터 + 시맨틱
)
for doc, dist in zip(res["documents"][0], res["distances"][0]):
    # chroma의 distance는 '거리'(작을수록 가까움). 코사인 유사도 ≈ 1 - distance
    print(f"sim≈{1 - dist:.3f}  {doc}")

# 중복 탐지: 새 기사가 기존과 임계값 이상 유사하면 경고
DUP_THRESHOLD = 0.92        # [주의] 표본으로 직접 보정할 값. 절대 기준 아님
new_article = "한국은행이 기준금리를 묶으며 물가 안정을 우선했다."   # a1과 거의 같은 내용
top = col.query(query_texts=[new_article], n_results=1)
sim = 1 - top["distances"][0][0]
if sim >= DUP_THRESHOLD:
    print(f"[중복 의심] 유사도 {sim:.3f} — 기존 기사 {top['ids'][0][0]} 와 매우 유사. 사람 확인 필요")
else:
    print(f"신규 기사로 판단(유사도 {sim:.3f}). 적재 진행")
```

**[주의]** `DUP_THRESHOLD`는 실제 CBS 기사 표본으로 *중복쌍/비중복쌍의 유사도 분포*를 그려 보고 정해야 한다. 임계값이 낮으면 정상 후속 기사까지 막고, 높으면 진짜 중복을 놓친다. 그리고 "중복 의심"은 어디까지나 **사람 확인 대상 후보**다.

**[팁]** 메모리 `Client()`는 프로그램이 끝나면 사라진다. 색인을 재사용하려면 `chromadb.PersistentClient(path="./store")`로 디스크에 저장한다.

### [실습 3] LLM 기반 콘텐츠 평가 — 루브릭 자동 채점 (75분)

1회차의 구조화 출력(JSON 스키마)을 그대로 써서, 기사 초안을 루브릭으로 자동 채점한다. 대량 기사 중 *먼저 볼 기사*를 추리는 데 쓴다.

```python
# pip install google-genai
import os, json
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])   # 키는 환경 변수로

# 루브릭 = 구조화 출력 스키마. 항목마다 점수(1~5)와 근거를 받는다.
schema = {
    "type": "object",
    "properties": {
        "accuracy":      {"type": "integer", "description": "정확성 1~5"},
        "balance":       {"type": "integer", "description": "균형성(편향 없음) 1~5"},
        "title_fit":     {"type": "integer", "description": "제목 적합성 1~5"},
        "reasons":       {"type": "string",  "description": "점수 근거 2문장 이내"},
        "needs_review":  {"type": "boolean", "description": "사람 검토가 시급한가"},
    },
    "required": ["accuracy", "balance", "title_fit", "reasons", "needs_review"],
}

article = "여기에 평가할 기사 제목과 본문을 붙여넣는다 ..."

resp = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=(
        "너는 CBS 뉴스 데스크다. 아래 기사를 루브릭으로 채점하라.\n"
        "정확성·균형성·제목 적합성을 각 1~5점으로, 근거와 함께 스키마대로 출력하라.\n\n"
        f"{article}"
    ),
    config=types.GenerateContentConfig(
        temperature=0.1,                       # 평가는 일관성이 중요 → 낮게(1회차)
        response_mime_type="application/json",
        response_schema=schema,
    ),
)

review = json.loads(resp.text)                 # 후속 코드가 바로 쓰는 딕셔너리
total = review["accuracy"] + review["balance"] + review["title_fit"]
print(f"합계 {total}/15  검토필요={review['needs_review']}  근거: {review['reasons']}")
```

**[주의]** 이 점수는 *초안*이다. 점수가 낮은 기사부터 사람이 검토하는 **우선순위 도구**로 쓰되, 점수만으로 발행·반려를 자동 결정하지 않는다. 채점 기준(루브릭)과 프롬프트는 6·7회차 프로젝트에서 재사용한다. **버리지 말 것.**

- [ ] 키워드 검색과 시맨틱 검색의 차이를 표로 구분할 수 있다.

- [ ] chromadb에 메타데이터와 함께 적재해 필터+시맨틱 검색하고, 임계값으로 중복을 탐지했다(실습 2).
- [ ] LLM에게 루브릭을 구조화 출력(JSON)으로 채점시켜 평가 초안을 받았다(실습 3).
- [ ] 임계값·평가 점수가 *초안*이며 사람 확인이 필요함을 설명할 수 있다.

## 6. 핵심 요약

- 임베딩은 의미를 좌표로 바꾼다. **"비슷한 문서 찾기 = 가까운 점 찾기"**이며, 보통 **코사인 유사도**로 잰다.
- 긴 글은 **청크**로 나눠 임베딩하고, **벡터 DB**가 인덱싱으로 top-k 최근접 검색을 빠르게 해 준다.
- **시맨틱 검색**은 표현이 달라도 의미로 찾는다. 정확한 고유명사엔 키워드와 함께 쓰는 하이브리드가 안정적이다.
- 같은 "가까운 점 찾기"가 **중복 탐지·추천·RAG**로 갈라진다. 임계값은 데이터로 직접 보정한다.
- LLM 루브릭 채점은 1회차 **구조화 출력**의 재활용이다. 임계값도 점수도 **초안 — 판정·발행은 사람의 몫.**

## 핵심 용어

| 용어 | 뜻 |
|---|---|
| 문서 임베딩 | 문장·문단·기사 한 덩어리를 의미가 담긴 하나의 벡터로 바꾼 표현 |
| 코사인 유사도 | 두 벡터의 방향이 얼마나 같은지(=의미가 얼마나 비슷한지)를 -1~1로 잰 값 |
| 청크(chunk) | 긴 문서를 임베딩·검색을 위해 나눈 일정 단위 조각 |
| 겹침(overlap) | 청크 경계에서 맥락이 끊기지 않도록 인접 청크를 조금 겹쳐 자르는 것 |
| 시맨틱 검색 | 질의와 문서를 벡터로 바꿔 *의미가 가까운* 문서를 찾는 검색 |
| 키워드 검색 | 질의 단어의 글자 일치로 문서를 찾는 전통적 검색 |
| 벡터 DB | 벡터를 저장·인덱싱해 최근접 이웃(top-k)을 빠르게 찾는 저장소(예: chromadb) |
| 최근접 이웃 검색 | 질의 벡터와 가장 가까운 k개의 벡터를 찾는 연산 |
| 임계값(threshold) | 중복·유사 판정의 경계가 되는 유사도 기준값. 데이터로 보정 |
| 콘텐츠 기반 추천 | 행동 로그 없이 콘텐츠 임베딩의 근접성으로 관련 항목을 추천하는 방식 |
| RAG | 먼저 검색한 근거 문서를 프롬프트에 넣어 LLM이 답하게 하는 검색 증강 생성 |
| 루브릭 | 정확성·균형성 등 항목별 점수 기준표. LLM 자동 채점의 틀 |
