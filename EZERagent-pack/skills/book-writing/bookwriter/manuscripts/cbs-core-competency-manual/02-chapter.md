## 1. STT는 어떻게 동작하나

뉴스 제작에서 음성→텍스트 변환(STT, Speech-to-Text)은 *첫 자동화 지점*이다. 인터뷰·기자회견·라디오 녹취를 코드로 받아쓰면, 그 텍스트가 검색·요약·기사 소재 추출 파이프라인의 입력이 된다. 그 출발점인 STT가 내부에서 무엇을 하는지부터 본다.

### 1.1 음향 모델·언어 모델에서 종단간 모델로

**[개념]** 전통적인 음성 인식은 세 부품의 조립이었다.

- **음향 모델(acoustic model)** — 소리 파형을 잘게 잘라, 각 조각이 어떤 음소(ㄱ·ㅏ·ㄴ…)일지 확률로 추정한다.
- **발음 사전(lexicon)** — 음소의 나열을 단어로 잇는 규칙.
- **언어 모델(language model)** — "이 단어 다음엔 어떤 단어가 그럴듯한가"로 문장을 다듬는다(1회차 LLM의 조상 격).

요즘 Whisper 같은 모델은 이 세 단계를 하나의 신경망으로 합친 **종단간(end-to-end) 모델**이다. 소리를 넣으면 곧바로 글자열이 나온다. 중간 부품을 따로 튜닝할 필요가 없어 다루기 쉽지만, 그만큼 "왜 이렇게 받아썼는지"를 들여다보기는 어렵다.

### 1.2 인코더-디코더 직관 — Whisper는 "듣고 받아쓴다"

**[개념]** Whisper류 모델은 1회차에서 본 트랜스포머의 **인코더-디코더** 구조다.

- **인코더** — 음성을 멜 스펙트로그램(시간×주파수의 소리 지도)으로 바꾼 뒤, 어텐션으로 "이 구간이 무슨 소리인지"를 압축한다.
- **디코더** — 그 소리 표현을 보면서, **다음 글자(토큰)를 확률적으로 하나씩 이어 붙인다.** 즉 받아쓰기도 결국 1회차의 "다음 토큰 예측"이다. 단지 앞 문맥에 *소리*가 더해졌을 뿐이다.

이 구조의 함의가 실무에서 중요하다.

- 디코더가 언어 모델을 내장하므로, **소리가 모호해도 "그럴듯한 한국어"로 메워 버린다.** 들리지 않은 말을 매끄럽게 지어낼 수 있다(STT판 환각).
- 학습 데이터에 드문 고유명사·신조어·사내 용어는 *흔한 비슷한 말*로 바꿔치기되기 쉽다(2장에서 교정).

### 1.3 WER·타임스탬프·세그먼트 — 결과를 재는 자

**[개념]** STT 결과의 품질은 감이 아니라 숫자로 잰다. 표준 지표가 **단어오류율(WER, Word Error Rate)**이다.

```
        치환(S) + 삭제(D) + 삽입(I)
WER  =  ──────────────────────────
              정답 단어 수(N)
```

- **치환(S)** — 다른 단어로 잘못 받아씀("노컷"→"녹화").
- **삭제(D)** — 있어야 할 단어를 빠뜨림.
- **삽입(I)** — 없는 단어를 끼워 넣음.

WER 0.10이면 단어 10개당 1개가 틀린 셈이다. 한국어는 조사·띄어쓰기 때문에 영어보다 WER이 높게 나오는 경향이 있으니, **절대값보다 같은 데이터에서의 상대 비교**(모델 A vs B, 교정 전 vs 후)로 쓰는 게 실용적이다.

**[개념]** STT 출력은 단순한 글 한 덩어리가 아니라 **세그먼트(segment)**의 목록이다. 각 세그먼트는 `시작 시각 · 끝 시각 · 텍스트`를 가진다. 이 **타임스탬프**가 자막 동기화(5회차), 영상 구간 검색(3회차), "몇 분 몇 초에 누가 무슨 말을 했나"를 가능하게 한다. 그래서 STT의 가치는 *글자*뿐 아니라 *시간 정보*에 있다.

| 단위 | 담는 정보 | 쓰임 |
|---|---|---|
| 단어(word) | 단어 + (정렬 시) 단어별 시각 | 정밀 자막, 키워드 위치 검색 |
| 세그먼트(segment) | 한 호흡의 문장 + 시작·끝 시각 | 자막 한 줄, 구간 점프 |
| 화자(speaker) | 누가 말했는지 라벨 | 인터뷰 화자 구분, 인용 귀속 |

## 2. 도메인 특화 STT — 뉴스 음성을 제대로 받아쓰기

범용 STT를 그대로 쓰면 뉴스 현장 음성에서 자주 무너진다. 왜 무너지는지, 어떻게 길들이는지를 본다.

### 2.1 뉴스 음성의 세 가지 함정

**[개념]** CBS 뉴스 녹취에서 오류가 몰리는 지점은 정해져 있다.

- **고유명사·인명·직함** — "한동훈"·"이재명" 같은 인명, "노컷뉴스"·"CBS" 같은 사명은 흔한 일반어로 바꿔치기되기 쉽다.
- **지명·기관명** — "옥천"·"세종"·"방통위" 등 지역·기관 이름.
- **전문용어·약어** — "AX(에이엑스)"·"PBL"·"앵커멘트" 같은 업계어.

여기에 **현장 잡음·겹쳐 말하기·사투리**가 겹치면 WER이 더 오른다. 핵심은 **틀리는 곳이 예측 가능하다**는 것 — 그래서 표적 교정이 통한다.

### 2.2 받아쓰기 전에 손대기: 초기 프롬프트와 사전

**[개념]** 오류를 사후에 고치기 전에, **모델이 받아쓰는 순간 힌트를 주는** 방법이 먼저다.

- **초기 프롬프트(initial prompt)** — Whisper에 "이 음성에 나올 법한 단어"를 미리 귀띔한다. 예: `"CBS 노컷뉴스, 한동훈, 이재명, 방송통신위원회, AX"`. 디코더의 언어 모델이 이 단어들 쪽으로 기울어, 고유명사 적중률이 오른다.
- **교정 사전(replacement dict)** — 그래도 자주 틀리는 패턴은 `오인식어 → 정답어` 매핑으로 후처리에서 일괄 치환한다(실습 2).

**[팁]** 부서별로 자주 나오는 고유명사 목록을 *한 번* 만들어 두면 초기 프롬프트·교정 사전 양쪽에 재사용된다. 1회차에서 평가셋을 버리지 말라고 했듯, 이 용어집도 자산이다.

### 2.3 화자 분리(diarization)와 강제 정렬(alignment)

**[개념]** 두 가지 후처리가 뉴스 녹취의 쓸모를 결정한다.

- **강제 정렬(forced alignment)** — Whisper의 세그먼트 타임스탬프는 다소 거칠다. 정렬 모델로 **단어 하나하나에 정확한 시각**을 다시 붙인다. 자막 싱크와 "특정 발언이 영상 몇 초 지점인지"를 정밀하게 만든다.
- **화자 분리(speaker diarization)** — "언제 누가 말했나"를 구간별로 갈라 `SPEAKER_00`·`SPEAKER_01` 같은 라벨을 단다. 인터뷰·토론에서 **발언을 사람에게 귀속**시켜, 인용의 주체를 명확히 한다.

이 두 기능을 transcribe와 한 흐름으로 묶어 주는 도구가 다음 절의 **WhisperX**다.

### 2.4 WhisperX — 받아쓰기 + 정렬 + 화자 분리 한 묶음

**[개념]** WhisperX는 Whisper에 (1) 빠른 일괄 추론, (2) 단어 단위 강제 정렬, (3) 화자 분리를 더한 파이프라인이다. 한 음성 파일에서 **정확한 타임코드 + 화자 라벨이 붙은 세그먼트**까지 한 번에 얻는 것이 목표다. 처리 순서는 다음과 같다.

```
음성 파일
  │  1) transcribe   → 텍스트 + 거친 세그먼트
  ▼
받아쓴 세그먼트
  │  2) align        → 단어별 정확한 타임스탬프
  ▼
정렬된 세그먼트
  │  3) diarize(선택) → 구간별 화자 라벨 부여
  ▼
[화자 · 시작 · 끝 · 텍스트] 목록  → 이후 파이프라인의 입력
```

**[주의]** 화자 분리에는 보통 Hugging Face의 화자 모델 접근 토큰이 필요하고, GPU가 없으면 느리다. 실습에서는 토큰을 환경 변수로 관리하고, 화자 분리는 *선택 단계*로 둔다.

## 3. STT → 기사 소재 파이프라인

1회차의 LLM API·구조화 출력을 STT 뒤에 이어 붙인다. 받아쓴 녹취에서 사람이 일일이 듣지 않고도 **인용·핵심 발언·소재 후보**를 뽑아내는 첫 자동화 흐름이다.

### 3.1 체이닝 설계 — 받아쓰기와 추출을 분리한다

**[개념]** 1회차 2.4의 프롬프트 체이닝을 그대로 적용한다. 한 번에 다 시키지 않고 단계를 쪼갠다.

```
[1단계 STT]            [2단계 교정]              [3단계 LLM 추출]
음성 → WhisperX  →  사전 치환 + LLM 교열  →  구조화 출력(JSON)
        텍스트          자연스러운 녹취           기사 소재 후보
```

단계를 나누면 좋은 점은 1회차와 같다 — 디버깅이 쉽고, 단계마다 모델·파라미터를 따로 고를 수 있다(받아쓰기는 STT 모델, 교열·추출은 LLM, 추출은 temperature 낮게).

### 3.2 추출의 출력은 구조화 데이터여야 한다

**[개념]** 추출 결과를 사람이 읽는 문장으로 받으면 후속 자동화가 막힌다. 1회차 실습 2의 스키마 패턴을 재사용해 **프로그램이 바로 쓰는 JSON**으로 받는다. 뉴스 소재 추출에 맞는 스키마는 대략 이렇다.

| 필드 | 내용 | 쓰임 |
|---|---|---|
| `quotes` | 인용할 만한 직접 발언 + 화자 + 타임코드 | 기사 인용문, 영상 클립 위치 |
| `topics` | 다뤄진 주제·이슈 목록 | 소재 후보, 태깅 |
| `story_candidates` | 기사화할 만한 소재 + 한 줄 근거 | 아이템 회의 입력 |
| `entities` | 등장한 인물·기관·지명 | 색인, 고유명사 검증 |

타임코드를 함께 담는 것이 핵심이다. "이 발언, 원음 몇 분 지점"을 알아야 검수와 영상 편집으로 곧장 넘어갈 수 있다.

### 3.3 검수 게이트는 사람의 몫

**[주의]** 자동 받아쓰기와 자동 추출 결과는 모두 **초안**이다(머리말 원칙 1·3 그대로).

- **인용은 반드시 원음 대조** — STT는 모호한 소리를 그럴듯하게 메운다(1.2). 인용문은 발행 전 *반드시* 원음을 다시 들어 한 글자까지 확인한다.
- **미공개 취재원·개인정보·화자 동의** — 녹취에는 미공개 취재원, 연락처, 사적 대화가 섞일 수 있다. 외부 STT·LLM API에 보내기 전에 처리 범위를 정하고, 동의·보안 정책을 확인한다.
- **타임코드로 추적 가능하게** — 추출물에 원음 위치를 남겨, 누구든 같은 근거로 재확인할 수 있게 한다(재현성).

## 4. 실습

> 공통 준비: 파이썬 3.10+. 1회차에서 쓴 `GEMINI_API_KEY` 환경 변수를 그대로 사용한다. 음성 파일은 짧은 CBS 뉴스 음성(예: 30초~2분 인터뷰 한 토막) 한 개를 `news.wav`로 준비한다. (사내 정책상 외부 API가 제한되면 강사가 안내하는 사내 게이트웨이/대체 키·로컬 실행을 사용한다.)

### [실습 1] WhisperX로 CBS 뉴스 음성 받아쓰기 (70분)

받아쓰기 → 정렬 → (선택)화자 분리까지 한 흐름으로 돌려, 화자·타임스탬프가 붙은 세그먼트를 출력한다.

```python
# pip install whisperx
import os
import torch
import whisperx

DEVICE = "cuda" if torch.cuda.is_available() else "cpu"
COMPUTE = "float16" if DEVICE == "cuda" else "int8"   # CPU면 int8로 가볍게
AUDIO = "news.wav"

# 1) 받아쓰기(transcribe) — 뉴스 고유명사를 초기 프롬프트로 귀띔
model = whisperx.load_model(
    "large-v3", DEVICE, compute_type=COMPUTE,
    asr_options={"initial_prompt": "CBS 노컷뉴스, 한동훈, 이재명, 방송통신위원회, AX"},
)
audio = whisperx.load_audio(AUDIO)
result = model.transcribe(audio, language="ko", batch_size=8)

# 2) 강제 정렬(align) — 단어별 정확한 타임스탬프
align_model, meta = whisperx.load_align_model(language_code="ko", device=DEVICE)
result = whisperx.align(result["segments"], align_model, meta, audio, DEVICE)

# 3) 화자 분리(diarize) — 선택. HF 토큰 필요, GPU 권장
#    임포트 경로는 버전에 따라 다르다(최신은 whisperx.diarize, 구버전은 whisperx 최상위).
if os.environ.get("HF_TOKEN"):
    from whisperx.diarize import DiarizationPipeline   # 구버전: whisperx.DiarizationPipeline
    diarize = DiarizationPipeline(
        use_auth_token=os.environ["HF_TOKEN"], device=DEVICE,
    )
    diar_segments = diarize(audio)
    result = whisperx.assign_word_speakers(diar_segments, result)

# 출력: [화자] 시작-끝  텍스트
for seg in result["segments"]:
    spk = seg.get("speaker", "SPEAKER_?")
    print(f"[{spk}] {seg['start']:6.1f}-{seg['end']:6.1f}  {seg['text'].strip()}")
```

**관찰 표** — 받아쓴 결과에서 틀린 곳을 분류해 본다.

| 오류 유형 | 예시(들린 말 → 받아쓴 말) | 건수 |
|---|---|---|
| 고유명사·인명 | | |

### [실습 2] STT 후처리 교정 — 사전 치환 + LLM 교열 (60분)

거친 받아쓰기를 (1) 고유명사 교정 사전으로 일괄 치환하고, (2) 1회차의 LLM API로 자연스러운 문장으로 다듬는다. 단, **사실을 더하거나 바꾸지 말 것**을 system으로 못 박는다.

```python
# pip install google-genai
import os
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# 1) 자주 틀리는 고유명사를 사전으로 일괄 치환(빠르고 확실한 1차 교정)
CORRECTION = {
    "녹화 뉴스": "노컷뉴스",
    "씨비에스": "CBS",
    "방통 위원회": "방송통신위원회",
    "에이 엑스": "AX",
}

def fix_terms(text: str) -> str:
    for wrong, right in CORRECTION.items():
        text = text.replace(wrong, right)
    return text

# 2) LLM 교열 — 받아쓰기의 흐트러진 문장만 다듬고, 내용은 보존
def polish(raw: str) -> str:
    resp = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=f"다음 받아쓰기 텍스트를 교열하라.\n\n{raw}",
        config=types.GenerateContentConfig(
            temperature=0.1,   # 사실 보존: 낮게
            system_instruction=(
                "너는 CBS 뉴스 교열기자다. 받아쓰기 오류로 끊긴 문장을 자연스럽게 다듬되, "
                "없는 내용을 추가하거나 사실을 바꾸지 마라. 불확실한 부분은 그대로 둔다."
            ),
        ),
    )
    return resp.text.strip()

raw_text = "어 그 녹화 뉴스 보도에 따르면 방통 위원회가 오늘 그 발표를 했고요"
stage1 = fix_terms(raw_text)
stage2 = polish(stage1)
print("원본 :", raw_text)
print("치환 :", stage1)
print("교열 :", stage2)
```

**[주의]** LLM 교열은 *문장 다듬기*까지만이다. 교열본은 검색·요약용 초안이고, **인용으로 쓸 문장은 반드시 원음과 대조**한다(3.3).

### [실습 3] 녹취 → 기사 소재 후보 JSON 추출 (80분)

실습 1·2를 거친 녹취 텍스트에서, 1회차 실습 2의 스키마 패턴을 재사용해 **기사 소재 후보를 구조화 출력**으로 받는다.

```python
# pip install google-genai
import os, json
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# 1회차 실습 2의 response_schema 패턴 재사용
schema = {
    "type": "object",
    "properties": {
        "quotes": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "speaker":   {"type": "string"},
                    "text":      {"type": "string"},
                    "timecode":  {"type": "string", "description": "예: 00:42"},
                },
                "required": ["speaker", "text", "timecode"],
            },
        },
        "topics": {"type": "array", "items": {"type": "string"}},
        "story_candidates": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "title":  {"type": "string"},
                    "reason": {"type": "string", "description": "기사화 근거 한 줄"},
                },
                "required": ["title", "reason"],
            },
        },
        "entities": {"type": "array", "items": {"type": "string"}},
    },
    "required": ["quotes", "topics", "story_candidates", "entities"],
}

# 화자·타임코드가 붙은 녹취(실습 1·2 결과를 한 덩어리로 정리한 것)
transcript = """[SPEAKER_00] 00:05 오늘 방송통신위원회가 지역 방송 지원 방안을 발표했습니다.
[SPEAKER_01] 00:42 현장에서는 실효성이 부족하다는 반응도 나옵니다."""

resp = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=f"다음 뉴스 녹취에서 인용·주제·기사 소재 후보·등장 개체를 스키마대로 뽑아라. "
             f"인용은 녹취에 실제로 있는 문장만 쓰고, 화자와 타임코드를 그대로 옮겨라.\n\n{transcript}",
    config=types.GenerateContentConfig(
        temperature=0.1,
        response_mime_type="application/json",
        response_schema=schema,
    ),
)

data = json.loads(resp.text)   # 후속 코드가 바로 쓰는 딕셔너리
for q in data["quotes"]:
    print(f"인용 [{q['speaker']} {q['timecode']}] {q['text']}")
print("소재 후보:", [s["title"] for s in data["story_candidates"]])
```

**[주의]** `quotes`의 타임코드는 원음을 되짚어 검수하기 위한 *위치 표지*다. 추출된 인용을 기사에 넣기 전, 해당 타임코드의 원음을 다시 들어 확인한다. 이 추출 스키마는 3회차(영상 분석)·5회차(숏폼 자동화)에서 재사용하니 **버리지 말 것.**

## 5. 체크리스트

- [ ] 음향·언어 모델 → 종단간 모델, 인코더-디코더로 STT 원리를 설명할 수 있다.
- [ ] WER의 세 오류(치환·삭제·삽입)와 세그먼트·타임스탬프 개념을 안다.
- [ ] 뉴스 음성의 오인식 지점을 알고 초기 프롬프트·교정 사전으로 대응할 수 있다.
- [ ] WhisperX로 transcribe→align→(선택)diarize를 돌려 화자·타임코드를 얻었다(실습 1).
- [ ] 사전 치환 + LLM 교열로 받아쓰기를 다듬었다(실습 2).
- [ ] 1회차 구조화 출력 패턴으로 녹취에서 소재 후보 JSON을 추출했다(실습 3).
- [ ] 인용은 원음 대조 검수, 미공개 취재원·개인정보 보호 원칙을 적용했다.

## 6. 핵심 요약

- STT는 인코더-디코더로 소리를 보며 **다음 토큰을 예측**하는 것 — 1회차 LLM과 한 뿌리이고, 그래서 모호한 소리를 그럴듯하게 메우는 **환각 위험**을 똑같이 갖는다.
- 품질은 **WER로 재고**, 가치는 글자뿐 아니라 **세그먼트·타임스탬프**에 있다.
- 뉴스 음성은 **고유명사·지명·전문용어**에서 틀리며, **초기 프롬프트 + 교정 사전 + 정렬·화자 분리(WhisperX)**로 길들인다.
- STT 뒤에 1회차 **LLM API·구조화 출력**을 체이닝하면 녹취가 **인용·소재 후보 JSON**으로 바뀐다.
- 자동 받아쓰기·추출은 **초안**이다. **인용은 원음 대조**, 취재원·개인정보 보호, 타임코드 기록으로 검수·재현성을 지킨다.

## 핵심 용어

| 용어 | 뜻 |
|---|---|
| STT | 음성을 텍스트로 바꾸는 기술(Speech-to-Text) |
| 음향 모델 | 소리 파형을 음소 확률로 추정하는 전통 STT의 부품 |
| 종단간 모델 | 음향·발음·언어 단계를 하나의 신경망으로 합친 STT 모델 |
| 인코더-디코더 | 음성을 압축(인코더)하고 글자를 이어 붙이는(디코더) 구조 |
| WER | 단어오류율. (치환+삭제+삽입)÷정답 단어 수로 STT 정확도를 잰다 |
| 세그먼트 | 시작·끝 시각과 텍스트를 묶은 STT 출력 단위 |
| 타임스탬프 | 단어·세그먼트가 음성의 몇 초 지점인지 나타내는 시각 정보 |
| 초기 프롬프트 | 받아쓰기 전에 나올 법한 단어를 모델에 귀띔하는 힌트 |
| 교정 사전 | 자주 틀리는 오인식어를 정답어로 일괄 치환하는 매핑 |
| 강제 정렬 | 단어 하나하나에 정확한 시각을 다시 붙이는 후처리(alignment) |
| 화자 분리 | 언제 누가 말했는지 구간별로 라벨을 다는 처리(diarization) |
| WhisperX | 받아쓰기+정렬+화자 분리를 한 흐름으로 묶은 STT 파이프라인 |
