## 학습 목표

이 회차를 마치면 다음을 할 수 있다.

- 프롬프트가 무엇이고, 같은 도구라도 프롬프트에 따라 결과가 왜 달라지는지 설명할 수 있다.
- 좋은 프롬프트의 5가지 구성요소(역할·맥락·과업·형식·제약)를 적용해 직접 프롬프트를 설계할 수 있다.
- 기사 초안 생성, 긴 문서 요약, 외신 번역을 위한 재사용 가능한 프롬프트 템플릿을 만들 수 있다.
- AI 결과물을 방송·뉴스 기준으로 검토하고 다듬는 절차를 이해한다.

## 1. 핵심 개념: 프롬프트 엔지니어링

### 1.1 프롬프트란 무엇인가

**[개념]** 프롬프트(prompt)는 AI에게 주는 **지시문**이다. 1회차에서 보았듯 LLM은 "다음에 올 그럴듯한 말"을 이어 붙이는 모델이다. 따라서 **어떻게 운을 떼느냐(프롬프트)에 따라 이어지는 결과가 통째로 달라진다.** 프롬프트 엔지니어링은 "원하는 결과가 나오도록 지시를 설계하는 기술"이다.

같은 도구를 쓰는 두 사람의 결과 품질 차이는 대부분 모델의 차이가 아니라 **프롬프트의 차이**다. 이것이 이 회차가 전체 교육의 토대인 이유다.

### 1.2 좋은 프롬프트의 5요소

**[개념]** 막연한 한 줄("기사 써 줘") 대신, 아래 다섯 가지를 채우면 결과가 극적으로 좋아진다.

| 요소 | 질문 | 예시 |
|---|---|---|
| 역할(Role) | AI가 누구처럼 답해야 하나? | "너는 20년 차 방송 뉴스 데스크다" |
| 맥락(Context) | 배경·대상·목적은? | "지역 시청자 대상, 저녁 종합뉴스용" |
| 과업(Task) | 정확히 무엇을 시키나? | "아래 보도자료를 뉴스 리포트로 재구성" |
| 형식(Format) | 출력 모양은? | "리드 2문장 + 본문 4문단 + 앵커 멘트" |
| 제약(Constraints) | 지켜야 할 규칙은? | "추측 금지, 350자 이내, 수치는 원문 그대로" |

**[팁]** 다섯 개를 다 쓸 필요는 없다. 하지만 **역할·과업·형식**은 거의 항상 넣을수록 좋다.

### 1.3 자주 쓰는 프롬프트 패턴

| 패턴 | 언제 쓰나 | 방법 |
|---|---|---|
| 예시 제시(few-shot) | 원하는 문체·형식이 명확할 때 | "이런 식으로: (예시 1~2개)"를 함께 제공 |
| 단계 지시 | 복잡한 작업일 때 | "1단계… 2단계… 순서대로 진행" |
| 출력 형식 고정 | 표·목록으로 받고 싶을 때 | "표로, 열은 A/B/C"처럼 명시 |
| 페르소나 부여 | 톤을 통제하고 싶을 때 | "친근한 유튜브 진행자 말투로" |
| 자기검토 요청 | 정확성이 중요할 때 | "작성 후, 사실 확인이 필요한 부분을 따로 표시" |

### 1.4 나쁜 프롬프트 → 좋은 프롬프트

| 나쁜 예 | 문제 | 좋은 예 |
|---|---|---|
| "이 글 요약해 줘" | 길이·형식 불명확 | "아래 글을 3개 불릿(각 40자 이내)으로 요약, 핵심 수치 포함" |
| "기사 써 줘" | 주제·톤·분량 없음 | "아래 자료로 350자 스트레이트 기사, 6하원칙 충족, 추측 배제" |
| "번역해 줘" | 톤·용어 기준 없음 | "아래 영문을 방송용 한국어로, 고유명사는 원어 병기, 의역 허용" |

**[주의]** 프롬프트가 길수록 좋은 것은 아니다. **명확함**이 핵심이다. 불필요한 수식어보다, 위 5요소를 구체적으로 채우는 것이 낫다.

## 2. 뉴스·방송 업무용 프롬프트 템플릿

**[개념]** 매번 프롬프트를 새로 쓰지 말고, 업무별 **템플릿**을 만들어 두고 빈칸만 바꿔 쓰는 것이 실무의 핵심이다. 아래 세 가지는 바로 복사해 쓸 수 있는 출발점이다.

### 2.1 기사 초안 생성 템플릿

> 너는 CBS 보도국 데스크다. 아래 [원자료]를 바탕으로 저녁 종합뉴스용 스트레이트 기사를 작성하라.
> - 형식: 리드 2문장 + 본문 3~4문단
> - 분량: 400자 내외
> - 원칙: 6하원칙 충족, 원자료에 없는 사실·수치 추가 금지, 추측·논평 배제
> - 사실 확인이 필요한 표현은 문장 끝에 [확인]으로 표시
> - [원자료]: (여기에 붙여넣기)

### 2.2 요약 템플릿

> 아래 [문서]를 세 가지 길이로 요약하라.
> 1) 한 문장 요약(60자 이내)
> 2) 뉴스 리드(2문장)
> 3) 핵심 불릿 5개(각 40자 이내, 수치·고유명사 보존)
> 원문에 없는 내용은 넣지 말 것.
> - [문서]: (여기에 붙여넣기)

### 2.3 번역 템플릿

> 아래 [외신]을 방송용 한국어로 번역하라.
> - 자연스러운 한국어 우선(직역체 금지), 필요 시 의역 허용
> - 인명·기관명은 한국어(원어) 병기
> - 숫자·단위·날짜는 한국식 표기로 환산하되 원문 수치 보존
> - 번역 후, 의미가 모호해 확인이 필요한 문장을 따로 표시
> - [외신]: (여기에 붙여넣기)

**[팁]** 이런 템플릿을 사내 공용 문서로 모아 두면 팀 전체의 결과 품질이 평준화된다. 6회차(업무 자동화)에서 이 템플릿들을 자동화 흐름에 연결한다.

## 3. 실습

### [실습 1] 5요소로 기사 초안 만들기 (50분)

1. 실제 보도자료(또는 사내 샘플) 한 건을 준비한다.
2. 먼저 **막연하게** "이걸로 기사 써 줘"라고만 입력해 결과 A를 받는다.
3. 다음으로 2.1 템플릿(5요소 적용)으로 결과 B를 받는다.
4. 두 결과를 아래 표로 비교한다.

| 비교 항목 | 결과 A(막연) | 결과 B(템플릿) |
|---|---|---|
| 6하원칙 충족 | | |
| 원문에 없는 내용 추가 | | |
| 분량·형식 준수 | | |
| 바로 쓸 수 있는 정도(상/중/하) | | |

### [실습 2] 3단계 요약 (30분)

긴 자료(보고서·회의록 등)를 2.2 템플릿으로 요약하고, 각 단계 결과가 실제로 쓸 만한지 평가한다. 특히 **수치·고유명사가 보존됐는지** 원문과 대조한다.

| 요약 단계 | 결과 | 원문 대비 정확성 | 활용처 |
|---|---|---|---|
| 한 문장 | | | SNS·카드뉴스 제목 |
| 리드 2문장 | | | 기사 도입 |
| 불릿 5개 | | | 영상 자막·요약본 |

### [실습 3] 외신 번역 + 톤 다듬기 (40분)

외신 한 단락을 2.3 템플릿으로 번역한 뒤, "방송 앵커가 읽는다"고 가정하고 한 번 더 다듬게 한다(예: "위 번역을 앵커가 읽기 좋게 호흡을 끊어 다시 써 줘"). 직역체가 어떻게 방송체로 바뀌는지 관찰한다.

**[주의]** 번역·요약 결과도 **사실 검증 대상**이다. AI는 숫자나 고유명사를 미묘하게 바꾸기도 한다. 발행 전 원문 대조는 필수다.

## 4. 체크리스트

- [ ] 프롬프트 5요소(역할·맥락·과업·형식·제약)를 설명할 수 있다.
- [ ] 막연한 프롬프트와 5요소 프롬프트의 결과 차이를 직접 확인했다(실습 1).
- [ ] 기사·요약·번역용 나만의 템플릿을 하나 이상 저장했다.
- [ ] 요약·번역 결과에서 수치·고유명사 보존 여부를 원문과 대조했다.
- [ ] AI 결과물은 초안이며 발행 전 검증이 필요함을 체득했다.

## 5. 핵심 요약

- 결과 품질의 차이는 대개 모델이 아니라 **프롬프트**에서 온다.
- 좋은 프롬프트 = **역할·맥락·과업·형식·제약**을 구체적으로 채운 것.
- 업무별 **템플릿**을 만들어 두면 빠르고 일관된 결과를 얻는다.
- 요약·번역·기사 모두 AI 결과물은 *초안*이며, 수치·고유명사·사실 검증은 사람의 몫이다.

## 6. 다음 회차 예고

**3회차 · LLM 기반 콘텐츠 작성 심화** — 한 번의 프롬프트를 넘어, *프롬프트 체이닝*으로 대본을 단계적으로 완성하고, 기사 중복 판단과 팩트체크를 AI로 보조하는 방법을 다룬다. 이번 회차의 템플릿이 여러 단계로 연결되기 시작한다.
