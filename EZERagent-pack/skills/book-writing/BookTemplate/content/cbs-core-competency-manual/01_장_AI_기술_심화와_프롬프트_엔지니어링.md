## 학습 목표

이 회차를 마치면 다음을 할 수 있다.

- LLM이 토큰·임베딩·어텐션을 통해 "다음 토큰"을 예측하는 과정을 자기 말로 설명할 수 있다.
- temperature·top-p·max tokens 등 디코딩 파라미터가 결과에 어떤 영향을 주는지 이해하고 의도적으로 조절할 수 있다.
- system/user 역할 분리, few-shot, Chain-of-Thought, 구조화된 출력(JSON) 등 고급 프롬프트 기법을 상황에 맞게 쓸 수 있다.
- LLM API를 파이썬으로 호출하고, API 키를 안전하게 다룰 수 있다.
- 평가 기준을 세워 프롬프트를 반복 개선(최적화)하는 루프를 직접 돌릴 수 있다.

## 1. 핵심 개념: LLM은 내부에서 무엇을 하는가

전사교육에서 "LLM은 다음 토큰을 확률적으로 잇는다"고 배웠다. 핵심역량 과정에서는 그 한 문장을 분해해, 결과 품질을 끌어올리는 *손잡이*가 어디 있는지 찾는다.

### 1.1 토큰화와 임베딩 — 모델이 글자를 보는 방식

**[개념]** 모델은 글자를 그대로 보지 않는다. 먼저 텍스트를 **토큰**(단어 또는 단어 조각)으로 쪼개고, 각 토큰을 **임베딩**이라는 수백~수천 차원의 숫자 벡터로 바꾼다. 이 벡터 공간에서는 "의미가 가까운 말"이 "거리가 가까운 좌표"에 놓인다 — 이 성질은 4회차 검색·중복 탐지의 토대가 된다.

- 한국어는 영어보다 토큰이 더 잘게 쪼개지는 경향이 있어, 같은 글자 수라도 토큰 수가 더 많다. **토큰 수 = 비용·속도·컨텍스트 한도**와 직결되므로 감을 가져야 한다.
- 대략적 기준: 한국어는 글자 1자가 토큰 약 1~2개, 영어는 단어 1개가 토큰 약 1.3개 정도다(모델마다 다름).

### 1.2 어텐션 — "문맥을 읽는다"는 것의 의미

**[개념]** 트랜스포머(Transformer) 구조의 핵심은 **어텐션(attention)**이다. 다음 토큰을 고를 때, 모델은 앞에 나온 모든 토큰 중 *지금 중요한 것*에 가중치를 더 준다. "그 기자는 어제 부산에서 취재했고, **그**는…"에서 '그'가 누구인지 앞 문맥에 주목해 푸는 것이 어텐션이다.

실무적으로 중요한 함의는 두 가지다.

- **앞쪽 지시문이 강하게 작용한다.** 그래서 역할·규칙은 프롬프트 앞(특히 system)에 둔다(2.1).
- **문맥이 길어질수록 주의가 분산된다.** 핵심 지시를 멀리, 장문 속에 묻으면 놓치기 쉽다. 길면 쪼갠다(2.4).

### 1.3 확률적 생성과 디코딩 파라미터

**[개념]** 모델은 매 순간 "다음 토큰 후보들의 확률 분포"를 계산한다. 그 분포에서 *어떻게 하나를 뽑을지*를 정하는 것이 디코딩 파라미터다. 같은 프롬프트라도 이 값에 따라 결과가 달라진다.

| 파라미터 | 하는 일 | 낮을 때 | 높을 때 | 뉴스 업무 권장 |
|---|---|---|---|---|
| temperature | 확률 분포를 얼마나 평평하게 할지 | 일관·보수적(같은 답 반복) | 다양·창의적(불안정) | 사실 요약·추출: 0~0.3 / 아이디어: 0.7~1.0 |
| top-p | 누적 확률 상위 몇 %에서만 고를지 | 좁게(안전) | 넓게(의외성) | 0.9 안팎 기본, 정확성 필요 시 낮춤 |
| max tokens | 출력 최대 길이 | 잘림 | 길게 허용 | 용도에 맞게 상한 설정(비용 통제) |

**[팁]** 팩트가 중요한 작업(요약·메타데이터 추출·번역)은 **temperature를 낮게**. 카피·제목 후보를 여러 개 받고 싶으면 높여서 다양성을 얻는다. "결과가 매번 달라 불안하다"면 먼저 temperature부터 의심하자.

### 1.4 컨텍스트 윈도우와 비용

**[개념]** 모델이 한 번에 볼 수 있는 토큰 총량(입력+출력)이 **컨텍스트 윈도우**다. 긴 회의록·자막 전체를 넣을 때 이 한도를 넘으면 잘리거나 거부된다. 또한 대부분의 API는 **입력 토큰 + 출력 토큰 수로 과금**한다. 따라서 "필요한 만큼만, 구조적으로" 넣는 설계가 곧 비용 설계다.

## 2. 고급 프롬프트 엔지니어링

전사교육의 "5요소 설계"가 기본기였다면, 여기서는 결과를 *안정적으로* 만드는 기법을 다룬다.

### 2.1 역할 분리: system / user / assistant

**[개념]** API에서 프롬프트는 보통 세 가지 역할로 구성된다.

- **system** — 모델의 정체성·규칙·말투를 고정한다("너는 CBS 뉴스 교열기자다. 과장 없이 사실 중심으로 쓴다").
- **user** — 그때그때의 실제 요청·데이터.
- **assistant** — 모델의 응답(이전 턴을 대화에 이어 붙일 때 사용).

규칙은 user에 매번 반복하지 말고 **system에 한 번** 박아 두면 일관성이 올라간다.

### 2.2 Few-shot와 Chain-of-Thought

- **Few-shot(예시 제공)** — 원하는 입력→출력 쌍을 2~3개 보여 주면 형식·말투를 훨씬 잘 따른다. "설명"보다 "예시"가 강력하다.
- **Chain-of-Thought(단계적 사고 유도)** — "단계적으로 따져 본 뒤 결론을 내려라"처럼 추론 과정을 거치게 하면 분류·판단 정확도가 오른다. 단, **최종 출력에는 사고 과정을 빼고 결론만** 달라고 지시해 깔끔하게 받는다.

### 2.3 구조화된 출력(JSON)

**[개념]** 자동화의 핵심은 사람이 읽는 문장이 아니라 **프로그램이 바로 쓸 수 있는 데이터**를 받는 것이다. "결과를 아래 JSON 스키마로만 출력하라"고 지시하면, 후속 코드가 파싱해 파이프라인에 흘려보낼 수 있다. 최신 API들은 출력 형식을 JSON으로 강제하는 옵션(structured output / response schema)을 제공한다 — 실습 2에서 직접 쓴다.

### 2.4 프롬프트 체이닝과 분할

**[개념]** 한 번에 다 시키지 말고 **작업을 단계로 쪼개** 앞 단계 출력을 다음 단계 입력으로 넘긴다. 예: ①자막 전체 요약 → ②요약에서 기사 소재 후보 추출 → ③후보별 리드 문장 생성. 단계가 분리되면 디버깅·검수가 쉽고, 각 단계에 맞는 모델·파라미터를 따로 쓸 수 있다. 이 사고가 2~5회차 파이프라인의 골격이다.

## 3. LLM API 활용 기초

### 3.1 왜 웹 UI가 아니라 API인가

**[개념]** 웹 챗 화면은 한 건 처리에 좋지만, **반복·대량·자동화**에는 API가 필요하다. API로 호출하면 자막 100개를 코드로 한 번에 돌리고, 결과를 DB·스프레드시트에 바로 저장할 수 있다. 핵심역량 과정의 모든 파이프라인은 API 호출 위에 선다.

### 3.2 첫 API 호출과 키 보안

**[주의] API 키는 비밀번호다.** 코드·노트북·저장소에 키를 직접 적지 말고 **환경 변수**로 관리한다. 키가 유출되면 요금 폭탄·데이터 유출로 이어진다.

```python
import os
from google import genai  # pip install google-genai

# 키는 코드에 쓰지 않고 환경 변수에서 읽는다.
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

resp = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="다음 보도자료를 방송 뉴스 리드 2문장(150자 이내)으로. 과장 없이 사실 중심으로.\n\n[보도자료 본문]",
)
print(resp.text)
```

**[팁]** Claude·OpenAI도 구조가 거의 같다 — 클라이언트 생성 → 모델 지정 → 메시지 전달 → 텍스트 추출. CBS가 이미 쓰는 Gemini를 기본 예시로 삼되, 한 곳을 익히면 나머지는 옮겨 가기 쉽다.

```python
# Anthropic Claude 예시(구조 비교용)
from anthropic import Anthropic   # pip install anthropic
client = Anthropic()              # ANTHROPIC_API_KEY 환경 변수 자동 사용
msg = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=512,
    system="너는 CBS 뉴스 교열기자다. 과장 없이 사실 중심으로 쓴다.",
    messages=[{"role": "user", "content": "위 보도자료를 리드 2문장으로."}],
)
print(msg.content[0].text)
```

### 3.3 파라미터·비용 관리

호출할 때 1.3의 파라미터를 함께 지정한다. 정확성이 중요한 작업은 temperature를 낮추고 출력 상한을 둔다.

```python
from google.genai import types

resp = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=prompt,
    config=types.GenerateContentConfig(
        temperature=0.2,          # 사실 작업: 낮게
        max_output_tokens=400,    # 비용·길이 상한
        system_instruction="너는 CBS 뉴스 교열기자다. 사실 중심·과장 금지.",
    ),
)
```

**[팁]** 먼저 빠르고 싼 모델(flash 계열)로 파이프라인을 완성한 뒤, 품질이 부족한 단계만 상위 모델로 올린다. 처음부터 최고 모델을 모든 단계에 쓰면 비용만 커진다.

## 4. 실습

> 공통 준비: 파이썬 3.10+, `pip install google-genai`, 환경 변수 `GEMINI_API_KEY` 설정. (사내 정책상 외부 API 사용이 제한되면 강사가 안내하는 사내 게이트웨이/대체 키를 사용한다.)

### [실습 1] 디코딩 파라미터 비교 (60분)

같은 프롬프트에 temperature만 바꿔, 결과의 다양성과 안정성을 체감한다.

```python
import os
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])
prompt = "노컷뉴스 유튜브 숏폼 제목 후보를 5개 만들어 줘. 주제: 지역 소상공인 지원 정책."

for temp in (0.0, 0.4, 1.0):
    print(f"\n=== temperature={temp} ===")
    resp = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=prompt,
        config=types.GenerateContentConfig(temperature=temp),
    )
    print(resp.text)
```

**관찰 표**

| temperature | 결과 다양성 | 반복 실행 시 일관성 | 제목 품질(상/중/하) |
|---|---|---|---|
| 0.0 | | | |
| 0.4 | | | |
| 1.0 | | | |

토론: 사실 요약에는 어떤 값이, 제목 브레인스토밍에는 어떤 값이 맞는가?

### [실습 2] 기사 메타데이터 추출 — 구조화된 출력 (60분)

기사 본문을 넣어 **프로그램이 바로 쓸 수 있는 JSON**으로 분류 정보를 받는다. 자동 태깅·아카이브 색인의 출발점이다.

```python
import os, json
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

schema = {
    "type": "object",
    "properties": {
        "headline":  {"type": "string"},
        "category":  {"type": "string", "enum": ["정치","경제","사회","문화","스포츠","지역","기타"]},
        "keywords":  {"type": "array", "items": {"type": "string"}},
        "summary":   {"type": "string", "description": "2문장 이내"},
    },
    "required": ["headline", "category", "keywords", "summary"],
}

article = "여기에 기사 본문을 붙여넣는다 ..."
resp = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=f"다음 기사를 분석해 스키마대로 채워라.\n\n{article}",
    config=types.GenerateContentConfig(
        temperature=0.1,
        response_mime_type="application/json",
        response_schema=schema,
    ),
)

data = json.loads(resp.text)   # 후속 코드가 바로 쓰는 딕셔너리
print(data["category"], data["keywords"])
```

**[주의]** 모델이 분류한 카테고리·키워드도 *초안*이다. 자동 색인에 흘려보내되, 표본 검수로 정확도를 주기적으로 확인한다.

### [실습 3] 프롬프트 최적화 루프 (90분)

"좋은 프롬프트"는 한 번에 나오지 않는다. **평가 기준 → 측정 → 수정**을 반복해 만든다.

1. **평가 기준 정의** — 예: 보도자료→리드 변환에서 ①사실 왜곡 없음 ②150자 이내 ③방송 말투. 각 0/1로 채점.
2. **테스트셋 5건** — 실제 보도자료 5개를 고정 입력으로 둔다.
3. **반복** — 프롬프트 v1으로 5건을 돌려 점수 합계를 기록 → 약점(예: 글자 수 초과)을 보고 지시 보강 → v2로 재측정.

```python
cases = [ "...", "...", "...", "...", "..." ]   # 보도자료 5건

def score(src, out):
    s = 0
    s += 1 if len(out) <= 150 else 0            # 길이 규칙은 코드로 자동 채점
    # 사실성·말투는 사람이 0/1로 채점해 합산(반자동)
    return s

def run(prompt_tmpl):
    total = 0
    for src in cases:
        resp = client.models.generate_content(
            model="gemini-2.5-flash",
            contents=prompt_tmpl.format(src=src),
            config=types.GenerateContentConfig(temperature=0.2),
        )
        total += score(src, resp.text.strip())
    return total

v1 = "다음 보도자료를 방송 리드로 바꿔라.\n\n{src}"
v2 = "다음 보도자료를 방송 뉴스 리드 2문장, 공백 포함 150자 이내, 과장 없이 사실만으로 바꿔라. 글자 수를 반드시 지켜라.\n\n{src}"
print("v1", run(v1), "/ v2", run(v2))
```

작성한 평가 기준과 최종 프롬프트는 6·7회차 프로젝트에서 재사용한다. **버리지 말 것.**

## 5. 체크리스트

- [ ] 토큰·임베딩·어텐션으로 "다음 토큰 예측"을 설명할 수 있다.
- [ ] temperature·top-p·max tokens의 효과를 구분하고 작업에 맞게 설정할 수 있다.
- [ ] system/user 역할 분리, few-shot, CoT, 구조화된 출력을 구분해 쓸 수 있다.
- [ ] 파이썬으로 LLM API를 호출하고, 키를 환경 변수로 안전하게 다뤘다.
- [ ] JSON 스키마로 구조화된 출력을 받아 `json.loads`로 파싱했다(실습 2).
- [ ] 평가 기준을 세워 프롬프트를 v1→v2로 개선했다(실습 3).

## 6. 핵심 요약

- LLM은 토큰을 임베딩으로 바꾸고, 어텐션으로 문맥을 반영해 **다음 토큰의 확률 분포**를 만든 뒤, 디코딩 파라미터로 하나를 고른다.
- temperature는 결과의 보수성↔다양성을 조절하는 첫 손잡이다. **사실 작업은 낮게.**
- 안정적 결과의 3대 기법: **system 역할 고정 · few-shot 예시 · 구조화된(JSON) 출력.**
- 자동화는 API 호출 위에 서고, **API 키는 비밀번호처럼** 환경 변수로 다룬다.
- 좋은 프롬프트는 **평가 기준 → 측정 → 수정** 루프로 만든다.

## 핵심 용어

| 용어 | 뜻 |
|---|---|
| 토큰 | 모델이 텍스트를 다루는 최소 단위(단어·단어 조각). 비용·길이의 기준 |
| 임베딩 | 토큰·문장을 의미가 담긴 숫자 벡터로 바꾼 표현. 가까운 의미 = 가까운 좌표 |
| 어텐션 | 다음 토큰을 고를 때 앞 문맥 중 중요한 부분에 가중치를 더 주는 메커니즘 |
| 트랜스포머 | 어텐션을 기반으로 한 현대 LLM의 핵심 신경망 구조 |
| temperature | 출력의 무작위성(다양성)을 조절하는 디코딩 파라미터 |
| top-p | 누적 확률 상위 구간에서만 토큰을 고르는 샘플링 방식 |
| 컨텍스트 윈도우 | 모델이 한 번에 볼 수 있는 토큰 총량(입력+출력) |
| system 프롬프트 | 모델의 정체성·규칙·말투를 고정하는 최상위 지시 |
| few-shot | 입력→출력 예시를 함께 줘서 형식·품질을 끌어올리는 기법 |
| Chain-of-Thought | 단계적 추론을 유도해 판단 정확도를 높이는 기법 |
| 구조화된 출력 | 결과를 JSON 등 정해진 스키마로 받아 프로그램이 바로 쓰게 하는 것 |
| API 키 | API 사용 권한을 증명하는 비밀 문자열. 환경 변수로 관리 |
